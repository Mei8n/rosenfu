# 地域単位の読込・計算とマルチプレイ境界

2026-11-16。現行0.1の改善と将来設計を区別する。都市分割自体を目的にせず、計測でCPU・メモリ・通信の減少を確認する。TrainsWorldのコードは転載せず、設計の比較から独立実装する。

## 比較で確認したこと

固定参照: TrainsWorld `6b8ef91729e1e5812f3dcbaedd6c0a49fed6a84b`。

- [zones.md](https://github.com/circularsquare/trainsworld/blob/6b8ef91729e1e5812f3dcbaedd6c0a49fed6a84b/trainworld/docs/zones.md): 都市圏と非都市圏を需要地域として分割。線路の所有権やセーブを都市単位で別世界に分ける意味ではない。
- [demand-runtime.md](https://github.com/circularsquare/trainsworld/blob/6b8ef91729e1e5812f3dcbaedd6c0a49fed6a84b/trainworld/docs/demand-runtime.md): 駅の到達範囲に応じて都市需要packを保持し、都市間market packは別条件で保持する。閲覧のみの地域は軽量側で計算し、不要packを猶予後に解放する。WASM領域は縮小せず再利用。計算開始時には必要packが揃っていることを確認する。到達距離や猶予時間は同作のモデル固有で、そのままRosenfuへ採用しない。
- [architecture.md](https://github.com/circularsquare/trainsworld/blob/6b8ef91729e1e5812f3dcbaedd6c0a49fed6a84b/trainworld/docs/architecture.md): 旅客は個人の毎フレーム移動ではなく集団流動、列車描画と需要計算を分離する。これをマルチプレイ実装済みの証拠とは扱わない。

## 現行Rosenfuで採用する範囲

| 対象 | 現状と今回の変更 | 分割で切ってはいけないもの |
| --- | --- | --- |
| 水域 | 45地域の固定版を必要範囲で取得。今回、既設線の点対ごとの地域検索を一括集合照会に変更。投影境界は一回だけ計算し、同地域の重複結果生成を省く | 水域重複時のwet優先、境界接触、未取得と乾燥の区別、接続先の必要地域 |
| 道路・実在線 | 既存の地理タイルを利用。都市名へ再分割しない | タイル境界の接続、データ版、既設線が参照する取得根拠 |
| ワールド | 線路・駅・路線・系統は同じ権威あるグラフ | 都市を跨ぐ路線・系統、所有会社、Undo、保存参照 |
| 需要・流動 | 0.2以降。今回未実装 | 地域間OD、遠方新線による経路変更、会社間競争 |

一括地域照会は独立した区間の集合を使い、東京と札幌を結ぶ巨大な外接矩形へ変えない。関係ない中間地域の取得は増やさない。永続キャッシュやワールドrevisionの追加なしで同じ結果を返すため、Undo・読込・別ワールドへの切替後にも古い地域集合を再利用しない。既設線の判定方針・費用・保存形式は変更しない。

## マルチプレイに向けた現状監査と境界

現行はローカルの `WorldEditor` をMutexで直列化し、Rust側で候補を検証して確定する構造。道路の確定時にはworld tokenや原データ根拠、各編集にはexpected値などがあるが、すべての操作をマルチ対応と判断できる統一プロトコルはまだない。

今は、取得キャッシュと権威あるワールドの分離を維持し、読込順や画面位置が永続状態を直接書き換えないようにする。一括地域照会も読み取り専用で順序非依存。ネットワーク対戦を先に実装したり、架空の同期安全性を主張したりしない。

0.4の接続前に必要な実装:

1. サーバーが認証済み参加者と会社権限から操作を受け付け、共通revisionと一意command IDで順序を確定。クライアントからのWorldDraft全置換を対戦APIに流用しない。
2. 再送・途中参加で同一操作を二重適用しない。権威あるsnapshotと後続差分を原子的に切り替える。Undoは他人の変更を消す全体巻戻しにしない。
3. キャッシュはデータ版・地域IDをキーにした破棄可能な参照。必要な入力の版はホストで揃え、クライアントの通信失敗や画面外への移動をゲーム結果の違いにしない。未知データで続行する既存ルールはホストが一度だけ確定する。
4. 市境界を跨ぐグラフは一つの論理グラフとして扱う。地域別workerを採用する場合も境界ノードと需要を一意に所有し、重複計上を防ぐ。

## 需要分割の導入順（未実装）

0.2で小地域固定ODと全体参照計算を先に作る。静的需要packの版・範囲を固定し、同じ入力を全pack常駐と必要packのみで計算して総需要・経路配分が一致する試験を用意する。閲覧だけの地域と鉄道網が到達する地域を分けるが、都市間marketや遠方の乗換を単純な距離だけで落とさない。

その後CPU・RAM・再取得通信量・パン時の計算回数を計測して、需要packの保持/解放・軽量表示・依存関係による再計算を段階導入する。ワールド全体を常に複製するコスト、道路証拠の保持量、全国規模での水域集合照会は別々に計測する。0.1のGUI操作・描画改善と重複して同じファイルを変更しない。

## 無人進行と可視範囲からの独立（将来要件・未実装）

需要の基本単位はメッシュとし、長距離はゾーンを併用する。[需要・流動計画](demand-flow-plan.md)の人口/目的地からの潜在ODを、駅の有無や閲覧状態によって消さない。メッシュとゾーンの重複計上を防ぐ。

将来の権威側シミュレーションは、接続プレイヤーが0人でもheadlessで進行できる構造にする。世界時刻・操作順・モデル版・データ版・seed・計算epochを入力とし、クライアントの可視範囲、描画workerの有無、接続人数を需要・運行の計算対象を決める条件にしない。明示的な一時停止と、全員の切断は別の状態として扱う。

必要な計算packは、権威側の潜在OD・運行・地域間経路の依存関係から選ぶ。画面外でも需要や遠方への影響がある地域を落とさない。鉄道未到達の需要を集約して保持するなどの省力化は、全体参照計算との一致を確認して採用する。都市間の依存を可視地域だけで打ち切らない。

閲覧用packの解放は破棄可能な表示キャッシュにだけ作用させる。権威側の計算に必要な入力が未取得の場合と、クライアントの表示が未取得の場合を区別する。入力不足の扱いはホストがモデルごとに決め、クライアントの読込順で結果を変えない。既存の建設用水域の未知データ続行ルールを、将来の需要欠測へ無条件に流用しない。

受入試験は、同じ初期状態・操作列・世界時刻区間・seedで、表示なし/表示あり、0人/1人/複数人、異なる可視範囲を比較する。潜在OD・運行・輸送・収入の集計と権威状態が一致し、切断/再参加で時計や計算epochが二重進行しないことを確認する。必要pack常駐と遅延読込の結果も比較する。

ここで記載したheadless進行、需要・運行、ネットワーク同期は現行0.1で実装済みではない。需要は0.2以降、マルチ本体は0.4の計画であり、今回の地域集合照会の最適化と区別する。

## 検証

- 全国の登録境界、端点のみの接触、離れた複数地域、重複・順序入替、不正な末尾座標で旧独立照会と結果を比較する。
- セーブ読込後の遠方既設線、新規ワールド、既知水域の保持をsession回帰で確認する。
- `cargo test -p rosenfu-core --lib measure_batched_region_queries -- --ignored --nocapture` は10万線分の旧方式と一括方式の合成計測。壁時計の固定閾値をCI合否にしない。実機入力遅延やマルチプレイ性能の保証ではない。

2026-11-16 cloud Linuxでの合成計測（release、10万点対、1都市内の細分化線路）: 旧方式45.5〜49.5ms、一括方式4.3〜4.9ms。境界投影と重複した文字列/集合挿入を省く効果であり、通信速度・実機GUI・全国の実プレイで同じ比率を保証しない。地域ごとの都市需要分割そのものを実装した数値ではない。
