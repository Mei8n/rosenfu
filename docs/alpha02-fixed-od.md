# α0.2 固定OD参照計算

`rosenfu_core::demand::assign_fixed_od` は描画・セーブ・課金と分離した純粋関数。
実人口を生成する機能ではなく、入力期間あたりの**合成または開発者指定の固定移動人数**を扱う。

- OD IDは全入力で一意。メッシュ/ゾーンの同じ需要を重ねて渡さない。地域名は保存・分割の単位であり、探索境界ではない。長距離ODも残す。
- `trips: null` は不明、`0` は既知ゼロ。線路がなくても潜在ODは消さない。
- `PassengerLeg` は停車点間の有向辺。停車駅を飛ばす急行は飛ばした駅を辺端点にしない。`service_id/from/to` は文字列。鉄道は既存ID、バスは `bus:...` 等の衝突しない名前空間を使用する。
- 各ODへ複数のアクセス/退出駅と徒歩秒数を明示。駅名が同じ、駅グループが同じ、地域が同じ、というだけでは乗換辺を生成しない。`WalkLink` は片方向。双方向には2辺を渡す。
- 初回乗車と系統変更時に運行間隔の半分を待ちとして加算。同じ系統の連続区間では待ちを加算しない。運行間隔0は運休の表現には使わず、運休の辺を除く。運行側が停車・方向・走行時間を導出する。
- `ChoiceWeights` の徒歩/待ち/乗車の重み、乗換ペナルティ、logit温度は開発側で調整できるゲーム係数。既定値を実測・公的標準とは称さない。費用・運賃・容量・満足度・4分類は別工程。
- 有限の単純駅経路を探索し、候補と集約代替手段に一般化時間のlogitで人数配分。共有区間の相関補正やexact departure routingではない。頻度を無関係な系統と合算しない。
- `search_complete=false` の配分は候補途中の近似。候補なしで探索が打ち切られた人数は `unresolved_trips` であり、不達と断定しない。全探索で選択肢がなければ `unserved_trips`。未知ODは人数配分しない。
- 乗換後もOD人数は一度だけ数える。各経路の`services`は乗車列なので延べ乗車数は別に集計可能。課金・容量超過・実輸送をこの配分結果と同一視しない。
- この参照版は変更後に全量再計算する。入力順に依存しない安定順序で、同じ入力の再計算が課金や輸送を累積させることはない。全国規模性能・マルチプレイ実装は保証しない。

## 試験

`cargo test -p rosenfu-core demand:: --locked`

小地域、鉄道なし、不明/ゼロ、未接続、明示乗換、方向、環状、複数アクセス、並行競合、増発、新線、停車変更、地域境界を跨ぐ長距離（説明用・非実測）、人数保存、係数変更、探索打切り、入力順と繰返し、重複と非有限値を確認する。

運行・画面・保存との結合は別途統合検証が必要。このモジュール単体の試験成功はゲームUI全体の完成を意味しない。
