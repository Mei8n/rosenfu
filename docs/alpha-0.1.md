## 最短の進め方

1. 進行中の建設修正の対象SHAを固定し、既知不具合（特に削除Redo）を修正・確認する。
2. 新方式系統編集の参照保護と候補全体の原子的適用を決め、バックエンド→UI→保存往復の順で実装する。旧Track編集を作り直さない。複数路線結合など将来の全編集機能まで0.1へ追加しない。
3. 下の未確認操作を1件ずつ通し、基準版から変更された部分だけ回帰確認する。
4. 最終候補で小地域の「建設→駅→路線→系統→編集→保存→再起動」を完了する。
5. 3 OS起動・他担当者の手順再現・既知制約を確認して終了判定する。

## 実機確認の運用

ユーザーには一度に全件を依頼せず、操作1件・期待結果を示し、結果を受けて次へ進む。最終版SHAと実際に起動した版を一致させる。本番セーブを退避し、専用テストワールドを使う。新規会社でも保存先は単一スロットなので、既存本体とバックアップを安易に置換しない。

| 優先 | 次の1件 | 合格条件 |
| --- | --- | --- |
| 1 | 途中区間を削除→Ctrl+Z→Ctrl+Shift+Z | 同じ区間だけが復元・再削除され、他の駅や線形を変えない |
| 2 | 未着工経路の途中区間を削除 | 前後の残存形状・対象外駅・所属計画を保持 |
| 3 | 2点の完成経路をUndo→Redo | Undo後は余分な孤立点を残さず0点、Redoで元の経路 |
| 4 | 計画A編集→B→Aに戻りUndo/Redo | 他計画を巻き戻さず対象履歴を保持 |
| 5 | 複数経路のある計画だけ着工 | 対象だけ建設され、完了した空計画を整理。別計画は保持 |
| 6 | 同じ線路の同じ範囲に駅を重ねる | 重複を拒否して既存駅を変更しない |
| 7 | 3駅の路線から系統を新規作成し中間駅を通過にする | 路線所属と停車設定を独立して保持 |
| 8 | 最新変更を含む構造を保存して再起動 | 線形・駅・路線・系統・未着工計画が同じ |
| 9 | 手動保存後に計画を編集し、実時間2分後の自動保存から復元 | 最新自動保存の計画が戻り、手動保存を勝手に上書きしない |
| 10 | 未保存状態で終了/読込確認をキャンセル | 編集中の内容が残る。エラー時も空ワールドへ置換しない |

保存済み系統の再編集テストは実装後に追加する（上表7は新規作成のみ）。次の追加項目は本候補を実際に起動できる段階で1件ずつ確認する。

## 本候補で追加された操作の確認（GUI未確認）

- 平行敷設: 既設線を選び3〜30mの範囲で間隔を指定し、2点で確定する。元線は不変で独立した新線が計画に加わること。途中キャンセルで以前の下書きを失わないこと。複線設備や自動分岐の完成とは扱わない。
- 交差ホーム: 異なる線路上に交差するホームを置き、駅グループとして扱えること。同じ線路の重複ホーム拒否は維持する。
- グループ名と情報: 名前変更が共有名称に反映され、ホバー情報で駅と個々のホームを把握できること。物理ホームIDや既存路線・停車参照を置換しないこと。
- 個別ホーム撤去: 対象を確認して1ホームを撤去し、別ホームや参照中の設備を巻き添えにしないこと。許可できない参照があれば拒否し入力を保持すること。
- 保存往復: 上記の平行線・駅グループ・名前を保存し、schema 16対応の本候補で再開する。旧1〜15の保存はコピーを使って読み込み、元ファイルを読込だけで書き換えないこと。旧アプリでschema 16を開こうとしないこと。

## 確認済みと未確認の分離

本人の報告によるPC版 `edf89c` の確認済み項目: 環状接続、建設済区間撤去、Undo後孤立点からの再開、Ctrl直線スナップ解除、計画駅/建設駅の撤去Undo、アンカー移動後の保存再起動・Undo/Redo・着工、ワールド上書き・視点復元。

これは当該版・当該操作の確認であり、全体合格ではない。削除Redoは不具合報告あり。完成経路Undo等の後続修正に触れるケースは再確認し、無関係の確認済み操作を繰り返し依頼しない。未着工計画は保存対象になっており、旧方針の「終了時に必ず消える」を期待結果にしない。

各結果は `対象SHA / OS / 操作 / 期待結果 / 実結果 / 未確認・合格・不具合 / 関連修正` で記録する。3 OSのCIだけでGUI受入欄を合格にしない。
