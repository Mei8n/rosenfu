# 0.1アルファの要件と受入

α0.1のコードは [#256](https://github.com/Mei8n/rosenfu/pull/256) で `main` に統合済み。以下はα0.1の受入要件と残る確認項目であり、統合やCI成功を全項目の実機合格・公開配布とはみなさない。α0.2の現況は[実装方針と現況](implementation-plan.md)を参照する。

## 状態の読み方

以下は初期のPR #120候補より後の範囲を含む。由来線の切出し・部分高さ再設計・アンカー別高さは後続で統合されている。OFM道路・踏切・境界経路の根拠保存と接続/高さ対応は統合済み。全国45地域の水域取得と駅中心の水域判定は統合済み。取得接続の実装、全国全地点の正確性保証、実機検証は分ける。

## 最新の終了条件

小地域で建設・編集・保存・再開できることに加え、本人の追加指定により**線路数、7段階の高さと勾配、分岐、道路との踏切**を0.1の基本構造として実装する。以前の「分岐/縦断は0.1対象外」は撤回。完成時期を優先してこれらを後の版へ送らない。

| 必須分野 | 照合対象の実装範囲 | 残作業・合格条件 |
| --- | --- | --- |
| 起動・地図 | Tauri、F5、オンライン地図・帰属表示、3 OS CI | 最終SHAでネイティブ起動。CI成功はGUI受入を代替しない |
| 建設・計画 | 複数計画、線形・駅、延伸、区間撤去、Undo/Redo、範囲選択 | 既知不具合修正と参照保持・失敗原子性を実機確認 |
| 線路数 | 1線形に単線/複線/複々線の区間属性、敷設・描画・範囲変更・保存 | 部分変更が対象外区間を変えない。色帯を物理線路数と混同しない |
| 高さ・勾配 | 地上、上3段階、下3段階。1段6m、通常45‰/高速30‰/トラム45‰。縦断モデルと勾配検証 | 急勾配拒否・異高さ交差の非接続。部分高さ変更・アンカー別高さの連続性を実機確認。勾配を列車速度補正に使わない |
| 分岐 | 分岐・軌道接続モデルと敷設経路の追加 | 単複線のY字接続・途中分岐・参照/Undo/保存を最終GUIで確認。任意配線・運行鎖錠の完成とはしない |
| 道路・踏切 | OFM必要範囲取得、道路追従、踏切派生判定、境界経路の根拠保存・延伸/接続・高さ対応 | 取得失敗/coverage不足/不明な高さを完全確認扱いしない。全国実データの網羅性とGUI通し操作は未確認。store/経路容量制限は[保存仕様](storage.md)参照 |
| 水域 | 全国45地域の配信接続、詳細/粗水域判定、地上線路・地上駅中心の水域禁止 | 高架・開削の連続水面30km上限、深いトンネルの対象外を検証。正常な非提供と通信失敗・破損・未取得を混同しない。全国全地点の網羅性・境界精度や最終GUI合格は未保証 |
| 駅 | 計画/建設、名前・寸法、交差ホームの同一駅グループ | 計画と建設済みの見分け、個別撤去、経路参照の保持。乗換効果は未実装 |
| 路線・系統 | 地図駅選択、経路・中間所属駅、独立した停車設定、編集・複製、複数路線直通binding、色/形/記号と共有区間色帯 | 実経路と表示の一致、改名・複製の独立性、競合拒否。架空の乗客/収支/車両値を表示しない |
| 保存 | schema25専用、複数ワールド独立slot、manual/autosave/backup、自動保存自動開始、削除・復元、未保存・競合保護 | 旧1〜24は非破壊で拒否。現在の全構造を保存再開して維持。削除は復元可能な退避であり、現在の編集中内容を消さない。名前変更はα0.2。α0.1には未搭載 |

実在線路の自動取得/追従と出典保存は統合済み。道路追従の境界結合は統合済みだが、全国の実データ精度検証とGUI受入は未完。派生区間の参照保持を最終HEADで検証する。参照を保持できない変更は理由付きで全体を拒否し、無関係な駅・路線・系統まで一律に拒否しない。

バスとトラムの道路上設置は0.2で実装する。0.1の道路追従/踏切と区別し、[道路交通計画](road-transport-plan.md)で受入を管理する。

費用計算・課金は将来の実装とし、今回の構造変更に架空の費用や未承認の徴収を追加しない。列車運動、需要、ダイヤ、乗客流動、乗換/相乗効果、連絡通路・駅舎・経営・マルチの完成は別段階。基本設備の参照モデルは将来拡張を阻害しない。

## 受入の進め方

実装→独立レビュー→自動試験/3 OS CI→全変更の開発統合→統合済み不要ブランチ整理→改めて最終HEADで静的解析・相互作用確認→問題があれば修正/再統合・再検証→本人がGitHub Desktopで手動PC反映→実機受入の順。mainのマージは別途本人確認。ブランチ整理は統合済み・他用途なし・復元可能なものだけ。

本人には一度に**操作1件と期待結果**を伝え、結果を受けて次を提示する。確認済みの操作を理由なく再依頼しない。今回の変更と0.1必須を両方検査し、未適用修正をPCで試させない。現行形式の新規のテスト用スロットを作り、旧保存は削除しない。

| 順序 | 操作 | 合格条件 |
| --- | --- | --- |
| 1 | 最終候補を起動し、新規テストワールドを別スロットへ保存 | 旧保存・別slot・backupを変更しない |
| 2 | 計画内に独立経路を2本作り、後の経路をUndoで消す | 最初の経路を保持。着工成功後はそれ以前のUndo/Redo不可、失敗時は履歴保持。別の未着工計画は消さない |
| 3 | 区間撤去→Undo→Redo | 対象だけ変化し駅・路線・系統参照を保持。不可なら理由付き全体拒否 |
| 4 | 一部区間を単線→複線→複々線に変更 | 対象外の形・属性は不変。計画中はUndo/Redo可、既設線の変更成功は再開発の確定境界。保存で保持 |
| 5 | 地上から上下の各階層を接続 | 1段6mの連続縦断。45/30/45‰境界で判定、瞬間段差なし |
| 6 | 単複線Y字接続と途中分岐を作成・撤去 | 物理接続と表示一致、別高さの交差だけでは接続しない |
| 7 | 道路・水域を跨ぐ建設 | 対応実装を統合した後のみ試験。踏切と地上水域禁止を検証 |
| 8 | 路線起終点を地図選択し系統を別に作る | 中間駅は路線所属、系統停車は独立、系統の勝手な作成なし |
| 9 | 複数路線直通を作り、色/形/記号を編集・複製 | 経路と停車維持、コピー後独立、共有部分だけ色帯表示 |
| 10 | 全構造を保存して再起動 | 属性・縦断・分岐・駅・経路・停車・表示・計画を維持 |
| 11 | 別slotへ切替・autosave復元、未保存確認を取消 | 対象slotだけ処理、取消/失敗で入力と元worldを維持 |

自動試験では旧1〜24の拒否と元本体/backup不変、競合、壊れた参照、容量超過、失敗時原子性を確認する。実データへ意図的な破損を加えない。

[Undo/Redoの操作境界](undo-redo-policy.md)に沿って、計画横断、駅改名、系統/路線編集、参照プレビュー内の駅、旧Redo計画の復旧も確認する。保存では履歴を保ち、読込ではクリアする。

各結果を `対象SHA / OS / 操作 / 期待 / 実結果 / 未確認・合格・不具合 / 修正` で記録する。以前の本人確認（撤去Undo/Redo、接続、視点、計画保存等）はその版・操作に限定し、今回の現行形式・構造拡張全体を合格にしない。最終CI・GUI・未達必須項目が残る間は0.1完了と表示しない。
