| 線路・建設・駅 | Rosenfu は高さ・勾配、曲線、平行敷設、分岐、選択、Undo と独立した工事計画を実装。TrainsWorld の短い操作で実在線・平行線を建設する流れと、待避・折返し設備の案内は比較対象。標準ケースでクリック数とエラーからの回復を計測し、Rosenfu 固有の作図機能は残す。 |
| 路線・系統 | 起終点から中間駅を補う導線と別々の物理線・路線・系統は既存。Rosenfu も既存系統を複製できる。表示設定から「系統の操作」へ移し、削除と並べて見つけやすくした。既存の複製は物理経路・停車設定・関連する路線・表示設定を引き継ぐが、ダイヤや運転中の車両は引き継がない。TrainsWorld の停車順編集と、複製した系統をグループにまとめて表示する導線は別の比較項目。Rosenfu でも停車出現順が物理経路と一致しない場合に、順序だけを強引に変更しない。 |
| 運行・競合 | 参考元は列車が通る時刻を主に事前計算し、一部の曜日・便で追従と追越しの個別プロファイルも使う。Rosenfu は実行中の資源予約と後端解放を持つが、待避・ホーム・複数ダイヤ併用の適用条件が狭い。実予約を削除して見かけだけ揃えない。 |
| ダイヤ・車両 | TrainsWorld は時間帯ごとの編成数または目標間隔を直接設定。Rosenfu の時間帯指定は対象・期限が限定され、編成試算は運行に適用しない。最初に1往復を設定する手数、時間帯の連続性、目標に届かない理由、走行中の列車を壊さない更新で比べる。系統一覧の稼働中編成数と保有編成数は別。 |
| バス・トラム・船 | Rosenfu の踏切・道路追従は既存の道路データを利用。バス手動停留所・道路上トラムは検証済み形状に制約があり、一部の道路経路で復路やモード併用ができない。TrainsWorld の自動停留所・乗換点、広い道路経路、船とは差がある。比較対象であることと、船を今の配布版に入れることは別。 |
| 需要・流動 | TrainsWorld は用途別の実データ推計、混雑・時間・費用での経路選択、段階キャッシュとサービス変更時の再計算を公開。Rosenfu には固定ODの試算と観測再生があるが、同じ人口ベース・都市間性能や観測値ではない。全国自動生成・朝夕の需要方向変化は今の固定ODと混同しない。建設候補探索も旅客経路算定と分ける。 |
| 財務・経営 | 参考元の建設・運行費、利益・混雑の地図表示に対し、Rosenfu の財務と収支は未実装。稼働列車や仮の試算から実績の乗客数・収益を作らない。 |
| 保存・再開・大規模編集 | Rosenfu はファイル上のセーブ、オートセーブ、復旧、履歴に明示的な互換性を持つ。参考元は保存のバックグラウンド化などを記載。ロード時間、ピークメモリ、入力応答と確定処理を測定し、速度のために復旧・参照検証を撤去しない。 |

| 共有・マルチ・配布 | TrainsWorld のブラウザ利用とコミュニティ共有は、Rosenfu のデスクトップ配布、オフライン、将来のプレイヤーホストとは異なる。非公開になっている参考元のサービス側実装は比較不能。QAは公開リリースではなく、再現可能な内部ビルドとして評価する。 |

## 同条件で先に再現するケース

- **運行**：単線対向、同方向の緩急（待避なし／あり）。停車・待機・通過・後端解放の時刻、運行が止まらないこと、所要時間とOD試算を別々に記録する。ケースごとにセーブ再開で同条件を再現する。
- **操作**：新規ワールドで線路・駅→路線→系統→運行、途中駅を変更→Undo、路線・系統を切替。操作回数、誤操作時の復旧、キーボードのみで操作可能かを記録する。
- **実道路**：バス2停留所→途中停留所追加→運行、道路上トラム建設→運行、セーブを開き直す。タイル取得不能、経路拒否、走行不能を別々に記録する。
- **性能**：実用的な小規模と大規模な同一データを固定して、入力応答、エンジン確定、地図描画、保存・再読込を分離する。測定なしに「軽くなった」としない。

内部資料: [TrainsWorld アーキテクチャ](https://github.com/circularsquare/trainsworld/blob/3e9c056469b7a87383c2211c30427fedfbbebe66/trainworld/docs/architecture.md)、[列車タイミング](https://github.com/circularsquare/trainsworld/blob/3e9c056469b7a87383c2211c30427fedfbbebe66/trainworld/sim/src/track/timing.rs)、[需要ランタイム](https://github.com/circularsquare/trainsworld/blob/3e9c056469b7a87383c2211c30427fedfbbebe66/trainworld/docs/demand-runtime.md)、[Rosenfuの運行](alpha02-operation.md)、[Rosenfuの固定OD](alpha02-fixed-od.md)。

## 改善後の確認状況

| 確認できた差 | この変更で対応した範囲 | 次に確認する差 |
| --- | --- | --- |
| 系統が増えると関連する系統が見つけにくい | 関連路線で絞り込み、系統名・路線名で検索。直通系統は複数の関連路線から探せる。中間の経由順は物理経路を検証して編集 | 初見プレイの操作回数、同じ駅を複数回通る系統の地図編集 |
| 編成数の試算を運行へ反映しづらく、時間帯設定の編集が限定的 | 試算した間隔を既存の簡易ダイヤへ適用。時間帯ダイヤを1〜30日繰り返し、対象系統だけ元の簡易ダイヤに戻す | 保有編成を直接管理するモデル、複数系統にまたがる自動待避 |
| 画面外の車両が表示枠を使い、曲線で列車が消える | ビューポートを先に判定し、検証済みの単独曲線で位置を描く。同じ走行区間で受け取った位置の間だけ補間し、位置を証明できる停車中の列車も表示。OSで動きを減らす設定をオンにした時は再生中の補間も中止 | バスの停車と複雑な分岐の正確な表示、実機描画計測 |
| バスの復路が作れないときの運行設定が分かりにくい | 通常のバス新設で片道・往復を明示、途中停留所を往路順で表示。復路エラーで勝手に片道へ変更しない | 実地図の通し試験、広域併用軌道と乗換 |
| 時間以外の経路選択と費用比較が見えない | 固定ODで入力した運賃・費用を使う任意の試算。配分が確定した場合だけ仮の費用差を表示 | 実人口に基づく需要、会社の実際の収支・建設費。朝夕の需要方向は採用済みの0.3以降 |
| 保存上限の検査が同じデータの整形を繰り返す | 保存形式を変えず、事前判定をコンパクト形式の一回の計測に短縮 | 全国規模の部分読込、実機で編集・ロードを計測 |

上表は、差が消えたことを両製品の実プレイで確かめた記録ではない。保存互換・道路の通行可否・実行中の進路保護は維持し、未対応の推測値は確定データとして出さない。

### 実道路の小区間試験

2026-11-25 JST に、統合済みの `d2dbf2e` を使って下記を検証。地図上で実際にクリックするデスクトップ試験ではなく、実地図タイルを使ったフロントエンドのデコーダーとネイティブ本体のヘッドレス試験。比較相手の同地点での挙動は未測定。

- 東京の z14 / 14552 / 6451: 約211 mの確認済み道路にゲーム内停留所を3つ確定し、1台のバスが往復で途中停留所を含む4回の到着を処理。運行途中に保存・再読込し、取得なしで経路・停留所・車両位置を維持。欠損・改変タイルでは状態を変えず拒否。2026-11-01 の提供元アーカイブと2026-11-22のタイルでそれぞれ通過。両版では同じ形状でも地物番号が異なるため、同じデータとしては扱わない。
- 長崎・出島の z14 / 14102 / 6613: 提供元の実道路上の約47 mを通常の併用軌道として検証し、試験用ホーム間で往復運行・保存・再読込。確認済みの道路形状を利用し、隣接する実在トラム線を道路と誤認しないことや、道路証拠の欠損・改変時の拒否も検証。実在の停留場や運行を再現したものではない。

地図配信のメタデータはクラウドからタイムアウトする場面があり、標準のオンライン画面操作および複数タイルをまたぐ経路は別途確認が必要。タイルの生データはこのリポジトリに含めない。


### 車両表示の密集状態

ネイティブからの運行スナップショットを模した、同一画面内に列車32・バス32の
SVGコンポーネント統合試験を追加。定期取得で同一区間内の2位置だけが補間され、
OSの視覚効果変更イベントで進行中の補間が全て止まり、追加の運行問い合わせは
発生しないことを確認する。停車・別走行区間・別の道路弦では補間しない。
この試験はReactとDOMの検証で、実機の描画・フレームレート計測ではない。
