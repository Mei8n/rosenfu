# 独立した複数の線路計画

未着工の手描き線路を複数保持できます。経路が離れていても互いを接続しません。

- 1つの計画に複数の独立経路と駅を保持する。終端の再クリックで経路を終え、そのまま次の経路を描ける。ダブルクリック速度は要求しない。
- 計画を分けるのは「別の線路計画を追加」を明示した時だけ。
- 点列・線路種別・設計速度・Undo/Redo履歴は経路ごとに保持。直線/曲線は自動で描き分ける。
- 計画名は任意（最大80文字）。未入力なら「計画 N」。路線名や建設済み線路名とは別。
- 選択計画の全経路・駅を原子的に着工する。他計画は着工しない。失敗時は全て保持する。
- 手描き・参照経路・延伸の現在の契約は[建設操作](track-construction-interaction.md)と[参照延伸](reference-extension-provenance.md)を参照。

## 保存に関する制限

現段階の計画はUI内の一時データです。ワールドファイルの既存形式は変更していません。
未着工計画があっても建設済みワールドを保存できます。計画も保存・復元します。読込には未保存変更がある場合だけ破棄確認を表示します。駅設定・会社・路線・系統の未適用編集は、従来どおり手動保存前に適用または破棄が必要です。
アプリを閉じると計画は失われるため、画面内にも明示しています。
再起動をまたぐ計画保存・復元は未実装です。着工後の線路は通常のワールド保存対象です。

## 検証

`npm test -- src/IndependentPlans.test.tsx`:
互いに離れた計画の同時表示、切替、個別着工、失敗後保持、Undo/Redo、個別消去、読込確認を確認。
Windows実機での操作確認は別途必要です。

### 終了確認

未適用の計画または未保存の変更がある場合、ブラウザの `beforeunload` と
Tauri のウィンドウ終了イベントをガードします。Tauri では「編集に戻る」または
「破棄して終了」を選びます。イベント登録が失敗した場合は警告を表示します。
これは保存・バックアップではなく、強制終了・クラッシュ・OS終了の全ケースを保証しません。
Tauri の実機での終了イベントは別途確認が必要です。

## 既設線上の駅も計画する

既設線・未着工線を問わず、地図クリックは駅を計画に追加するだけです。駅タブで所属計画を選択し、計画別に着工します。線路を追加しない駅だけの計画も作れます。複数駅と新線・延伸を混在させても、着工失敗時は全件未着工のまま残ります。

既設線上の駅は敷設対象の線路IDと実際の座標を保持します。同一計画でその線路を延伸しても、着工時に元の物理位置を維持します。線形変更で駅が収まらなくなった場合は黙って移動・消去せず着工を拒否します。

schema 11は駅のみの計画を手動・自動保存します。schema 10以前の線路計画に所属する駅もそのまま読み込めます。旧保存の駅長を新規入力範囲へ切り詰めません。
