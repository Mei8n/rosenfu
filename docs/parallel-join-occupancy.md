# α0.2: 接続済みの直線複線における競合

両側とも2点1区間、同じ高さ・線路属性、接続座標が同じで水平面の接線が逆向きに一直線の普通複線では、既存の物理レーン対応が一対一で、通るレーンが確認できる場合に限り、接続部もレーン別に予約する。別々のレーンを使う対向列車は駅間を進める。同じレーン、単線、複線から単線への絞り、分岐、曲線・勾配など確認対象外の接続は従来の競合判定を保つ。複々線や信号・待避設備の追加ではない。

新規運行設定でこのレーン別予約を使ったセーブには `parallel_join_lanes` が入る。旧セーブの実行中の予約は読込時に書き換えない。条件を満たさなくなる編集後は該当運行を停止して再設定を求める。新しい予約を持つセーブを、このフィールドを知らない旧ビルドに戻して読み直すことはできない。戻す場合は更新前のセーブを使う。

駅間をまとめて予約する基本モデルや、ホームの収容力・閉塞ごとの追従・実際の踏切制御はこの変更の対象外。

## 先行列車の後端が抜けた区間

運行全体が、分岐・接続・勾配なしの平坦な直線複線（3区間以上）の短い直接経路に限られ、端部で折り返さない場合に限り、走行時間モデルに従って後端まで確実に通過した先頭側の区間を順次解放する。短い別区間へ向かう後続は先行列車の到着前に発車できるが、同じ全区間を走る後続は競合がなくなるまで待つ。引き続き次の停車駅まで一括で進路を確保してから発車する。複雑な緩急分離・待避線の自動選択・ホームの収容力や折返し制御は未対応。

この運行は保存内部形式3を使う。読込時に当該条件と経路を再検証し、地形を変えて該当しなくなった運行は既存の再設定待ちとして停止したまま保存・読込する。以前の内部形式2の運行をバックグラウンドで切り替えることはない。旧ビルドでは内部形式3の運行を含むセーブを開けない。

### 終着ホームの降車中は使用レーンを保持

上記の片道直線複線のうち、実際の終着ホームと車両が同じアンカー区間に収まる場合に限り、終着側の進行方向レーンを降車中も予約する。進路は通常の後端クリアと降車完了の遅い方で解放し、到着時刻自体に降車時間を加算しない。到着時点で後端通過を確認できる手前の区間は、その時点までに解放する。同じ駅でも、別の物理レーンは独立。降車が終わると車両はこの運行から退場する。留置、中間駅で次の進路を待つ車両の保持、渡り線・待避線の動的選択、駅グループ全体の収容力は対象外。

3区間、長さ40 m・最高72 km/hの確認条件で、先行車の到着は68.094秒、設定した降車時間は30秒。後続の同じレーンへの進入は70.094秒から98.094秒に、到着は138.188秒から166.188秒に変わる。別の物理レーンの列車は従来通り1秒で発車し、先行車の旅客到着時刻も変わらない。

ワールド保存形式や時刻表データ構造は変更しない。新規設定の当該運行だけが運行の内部形式5を使う。旧形式2〜4の運行は読込時に変更しない。形式5を含むセーブは旧ビルドでは読めないため、旧ビルドへ戻す場合は更新前のバックアップを使う。条件を外れる編集後は、再設定待ちの停止状態のまま保存・読込できる。

### 中間ホームで次区間が空くまで停車

直接指定した同方向・同一線形の片道2区間だけを対象に、中間ホームが接する1つの物理レーンを、到着から停車中、次の進路が空くまで保持する。次区間の予約成立時にそのレーンも同時に引き継ぎ、後端が通過した時に解放する。同じ駅名・駅グループでも別レーンは独立。列車が保有したレーンからは必ず同じ閉塞か進行方向の先の閉塞しか要求しないため、この対象内の待ち行列は循環しない。曲線や分岐、同一レーンの折返し、複数の中間停車、独立した退避線への進路選択は従来の扱いのままで、この仕組みの対象外。

単一の孤立した地上直線複線が1閉塞だけの場合も、停車する物理レーンと車両がその閉塞内に収まり、次の区間も同じレーンだけを使うと確認できれば、中間停車中にレーンを保持します。その間、後続の通過列車は進入できず、反対方向の別レーンの列車には影響しません。中間駅を発車しても先の線路が同じ閉塞なら予約は分けず、終着時の停車完了と後端通過の遅い方まで保持します。これは追従中の速度低下や設備容量の試算ではありません。新たに該当する保存は形式6でもこの条件に未対応の旧ビルドでは開けません。

5閉塞の再現条件では先行列車が中間駅に35.710秒で到着、停車予定終了は65.710秒。先の閉塞が147.020秒で空くまで停車し、後続は先行車の後端通過後の180.930秒に発車する（従来は先行車が停車中の37.710秒に発車）。対向の別レーンは1秒で発車。乗車中・発車待ちの時刻の記録は実際の進路予約から作り、計画時刻には上乗せしない。

ワールド保存形式は変更しない。対象運行に限り運行内部形式6を使用し、保存位置の閉塞所有と時系列を読み直す。形式2〜5の既存運行は切り替えない。旧ビルドでは形式6を含むセーブを開けないため、以前の版へ戻す場合は更新前のバックアップを使う。

### 経路を指定した待避線と前後の分岐器

地上の小さな平面待避線を明示的に構築し、同一方向の普通・優等系統それぞれに通る枝を指定した場合、普通列車が停車する枝の物理閉塞だけを次の進路まで保持する。停車位置でホーム・車両が両端の分岐器から離れ、待避線と本線が停車位置の全幅にわたって離れていることを確認する。別の枝を経由する優等列車は、入口の分岐器が空いてから進入できる。反対側の分岐器と合流後は共有するので、優等列車が先に進入したときは普通列車が発車を待つ。同じ枝を指定した場合は停車中の列車をすり抜けない。

線形4本・接続4個・分岐器2か所の再現条件で、優等列車が同じ枝を使う場合は進入553.209秒・到着732.454秒、別の枝を指定すると進入104.887秒・到着295.137秒。別の枝を使った場合、普通列車は予定の282.022秒から合流側が空く298.253秒まで待つ。分岐器の解放は駅間一括予約に従う保守的な近似で、実際の信号閉塞や自動の待避線選択ではない。

対象は地上・東西方向の限定形状、普通・優等の2系統、普通の中間停車1か所のみ。分岐を含む4線形の連結範囲から十分離れ、未使用の独立線路があるだけでは対象外になりません。一方、連結範囲に余分な接続がある場合や、近くに他の線形があり平面上の分離を確認できない場合は対象外です。それ以外の形状、複数の中間駅、対向運転、分岐器の途中解放、駅グループの収容力などは対象外で従来の扱い。外側のワールド保存形式はそのままで、このモデルを新規設定した運行だけ内部形式7を使う。以前の運行は更新せず、旧版は形式7を読み込めない。

この対象で進路が塞がれているときは、運行欄で「停車中の列車が同じ枝を使っている」と「別の枝を通る列車が合流側の進路を確保中」を区別します。前者では追い越す2系統の経路を別の枝に分けられるか確認できます。後者は分岐後に共用する先の区間が空くまでの待機です。停車時間は進路待ちとして数えず、表示は現在確認できている予約競合だけで、発車や通過の予測、自動での進路変更は行いません。

### 対向する2系統の待避順

本線と待避線の通り道を系統ごとに指定し、地上のホームと分岐器の間隔・線路の分離を確認できる小規模な構成では、同時に発車予定の対向2列車のうち、待避線に停まる列車を先に進入させます。通過列車は、相手の後端が進入側の分岐器を抜けるまで待ちます。すでに待っている列車や使用中の進路より優先することはありません。

繰り返しも、2系統の始発・終発・間隔が同じで、2列車の走行・停車・後端通過にかかる時間をすべて足しても次の発車まで余裕がある場合だけ対象です。間隔が短い・異なる、他の車両が残っている、通る枝や安全な間隔を確認できない場合は従来の発車順になります。新たな信号、待避線の自動選択、既存予約の解除は行いません。保存形式は変更しません。
