# 開発ロードマップ

更新日: 2026-11-16

文書の入口は[開発ドキュメント](README.md)。現在の実装状態と直近の順序は[実装方針と現況](implementation-plan.md)を管理元とする。

開発者2人と別途テスト担当を前提とした段階案です。追加参加者を見込んだ日程短縮は織り込みません。
作業時間と技術検証が未確定のため、期日は設定しません。版番号は目標を表し、リリース済みではありません。
段階構成と初回正式版の範囲は本計画での提案です。要件の採用方針と区別し、変更理由をPRに残します。

## 段階と完了条件

| 段階 | 主な範囲 | 次へ進むための確認 |
| --- | --- | --- |
| 0.1 アルファ | 起動・地図、駅・線路・路線・会社・系統、線路数1/2/4・7段階高さ/勾配・分岐、道路/水域判定・踏切、保存・再開 | 小地域で建設・編集し、再起動後も同じ構造を復元できる。3 OSで起動確認し、データ利用条件の調査結果を記録する |
| 0.2 アルファ | 共通時刻、簡易ダイヤ、列車運行、基礎OD需要と経路選択、バスとトラムの道路上設置、セーブデータの名前変更 | 新線・増発・停車駅変更で経路と利用者が変化する。鉄道未利用需要を区別できる。道路上のバス経路/停留所とトラム併用軌道を作成・編集・保存し、通行条件と交通モードを区別できる |
| 0.3 アルファ | 需要4分類、曜日・時間帯、競争と乗換、簡易経営、サンドボックス、基本分析 | シングルで建設→運行→流動確認→改善を一巡できる。複数会社の収支と流動を確認できる |
| 0.4 アルファ | ゲーム内ホスト、所有権、同期、途中参加・再接続 | 2人から5人へ試験を拡大し、他社の不正編集や再接続時の二重処理を防ぐ。共通時計と保存が整合する |
| 0.5 アルファ | 専用サーバー、無人進行、資金保護、パターンダイヤ、互換性基盤 | 同じワールドを各実行形態で再開できる。移行・復旧と手動ダイヤ保護を検証し、ベータ条件を満たす |
| 0.6 ベータ | 継続プレイ、操作性・性能・安定性とモデル調整 | 過去ベータのワールドを移行でき、公開した動作規模で重大な不具合が解消している |
| 1.0 RC | 正式版候補の検証、配布確認 | 既知のリリース阻害不具合がなく、復旧手順と各OSの配布物を確認済み |
| 1.0 正式版 | 初回範囲の公開 | リリースノート、既知の制約、互換性情報を公開する |

0.1の要件別状態・未確認事項・最短の確認順は[0.1受入](alpha-0.1.md)で管理する。開発ブランチ実装、main統合、自動検証、本人の実機確認を別々に扱い、未統合の修正を合格扱いしない。

路線・系統の安全な編集では明示的な関連付けと物理経路参照を検証する。旧形式を推測して移行しない。複数路線直通の実装と列車運行の完成は区別する。路線・系統の明示的単一/複数路線関連、形・記号を含む保存と参照を検証する。本人追加の線路数・高さ・分岐・道路踏切は0.1必須。費用計算は将来とし、未統合の必須項目は[0.1受入](alpha-0.1.md)で明示する。

0.1では小地域で検証しますが、製品の対象は日本全国です。全国を詳細に同時計算できるという保証は別途性能測定で判断します。
ベータは期限が来たら移行する段階ではありません。条件未達ならアルファを継続します。

## 0.2の道路交通

バスとトラムの道路上設置は採用済みの0.2要件であり、この文書更新による即時実装ではない。0.1の道路取得・追従・踏切を基盤として再利用するが、道路を取得できるだけでバス運行やトラム併用軌道の完成とはしない。実装順・受入・未決境界は[道路交通計画](road-transport-plan.md)を参照する。

## 0.2のセーブデータ名変更

本人の2026-11-16指定により、保存済みセーブデータの名前変更を0.2の実装予定に追加する。複数スロットの新規作成・別名保存とは別の操作として扱い、未実装の予定である。具体的な受入方針は[実装方針と現況](implementation-plan.md)の保存管理を参照する。

## 機能別の詳細計画

- 建設/改築、駅、路線/系統、暦、車両、地図、マルチの依存関係と未決事項は[実装方針と現況](implementation-plan.md)に集約する。
- 需要は[需要・流動計画](demand-flow-plan.md)に従い、メッシュ主体と長距離ゾーンを小地域から検証する。式・係数・データ配布条件・性能予算は未確定。 TrainsWorldの公開実装比較を踏まえ、0.2は固定OD・独立した旅客グラフ・待ち/経路配分、0.3は4分類と日本データ・運賃/容量、0.4は同じRust計算のホスト確定と再接続を段階検証する。具体的な受入fixture・未確定値・権利は同計画の第7節で管理する。
- 運賃は会社基本運賃と路線別率を維持し、日本向け通算や追加料金は[運賃案](japan-fare-model-notes.md)で検討する。
- 分岐・勾配・列車運動は[分岐・車両設計](junction-and-grade-design.md)を参照。端部延伸ができることは分岐完成を意味しない。

これらの採用方針を各段階へ割り当てる際は、依存関係・検証範囲と実装状況を更新する。同じ未完了一覧を複数文書に増やさない。

## ベータ開始条件

- [ ] 初回正式版の対象機能と未対応事項が確定し、上記0.1〜0.5の主要機能が動作する。
- [ ] 全国の任意地域で建設可能で、都市部・地方・地域間路線を検証済み。対応規模と動作要件を記載する。
- [ ] Windows / macOS / Linuxで起動、建設、運行、保存・再開を確認する。
- [ ] シングル、ゲーム内ホスト、専用サーバーで同じワールドを利用できる。
- [ ] [互換方針](world-compatibility.md)の移行・バックアップ・復旧試験を通過する。
- [ ] 所有権、参照ID、日付、運行データ、人口・需要・流動・資金の境界を固める。
- [ ] 将来の人口変動・子会社・詳細ダイヤを追加する模擬移行で、既存ワールドの意味を維持できることを確認する。
- [ ] データの配布・キャッシュ・帰属表示の条件と、ネット接続が必要な範囲を確定する。
- [ ] 保存破損、進行不能、所有権違反などの重大な既知不具合がない。テスト担当が再現手順付きで確認する。

## 1.0以降へ送る候補

沿線人口変動、子会社、詳細ダイヤグラムは1.0以降とする案です。バスとトラムの道路上設置は本人の指定により0.2必須へ移し、1.0以降へ延期しません。
未採用と決定したわけではなく、人口変動等を初回必須とする場合はベータ前の段階に追加します。
ベータ前に必要なのは、これらを追加しても既存の会社・設備・運行・人口を破壊しない構造と移行手段の検証です。

## 2人での進め方

画面・地図・建設と、エンジン・保存・計算を分担する案を基本に、データ境界は共同でレビューします。
担当を固定せず、Issueごとに主担当を1人置きます。テスト担当には各アルファの小さな配布物と確認手順を渡します。
各段階の終了時に未完了項目、性能、次の範囲を確認し、必要なら以降の計画を更新します。
