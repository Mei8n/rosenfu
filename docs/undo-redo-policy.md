# Undo / Redo の操作境界

## 原則

計画、路線、系統、駅の可逆編集は、ツール別ではなく実行した順の共通履歴で戻す。
新しい編集を行うと Redo は破棄する。失敗・実質的な変更がない操作では履歴を変更しない。
着工・既設設備の再開発が成功した場合は、それ以前の Undo / Redo を消去する。
保存・オートセーブは履歴を保持し、ロード・新規ワールドで消去する。
履歴はセッション専用で、セーブ形式には追加しない。バックエンドの World 履歴は最大50操作。

## 操作表

| 操作 | 扱い |
| --- | --- |
| 未着工線路・駅の作成、配置、移動、寸法・線種・高さ変更、削除 | 可逆な計画編集 |
| 路線作成・構成編集・改名 | 可逆な World 編集 |
| 系統作成・経路/停車駅変更・改名・表示設定・複製・路線紐付け・削除 | 可逆な World 編集 |
| 既設駅の改名、既設駅・線路の撤去 | 可逆な World 編集 |
| OFM計画・出典情報の同時追加 | World と計画を一操作として復元 |
| 計画の着工、直接の線路建設・延伸、直接の駅設置 | 成功時に確定し全履歴消去 |
| 既設ホーム寸法変更、既設線路の線種/線路数/高さ変更 | 成功時に再開発として確定し全履歴消去 |
| 地図視点移動、水域データ取得 | 編集履歴の対象外 |
| 手動保存・オートセーブ | 履歴保持 |
| ロード・新規ワールド | 履歴消去 |

## バックエンドとUIの契約

`undo_world_edit(expected_world)` / `redo_world_edit(expected_world)` はバックエンド自身が保持する
スナップショットを復元する。UIから任意の過去 World をそのまま適用するAPIではない。
`expected_world` の World 部分は現在のバックエンドと一致しなければ拒否する。
`construction_plans` と `view_state` はこの一致比較から除外する。

Worldと計画を同時変更した操作では、UIが**復元先の計画**と**現在のWorld部分**を渡す。
復元するID・路線・系統参照は履歴の値を維持し、その計画と組み合わせた全体を検証してから公開する。
検証に失敗した場合は World・履歴・Redo を一切動かさない。視点はUIから渡された値を維持する。
`world_edit_history` は revision / undoDepth / redoDepth を返す。revisionは成功編集・境界・Undo/Redo・ロードで進む。

計画だけの編集履歴と World 履歴の時系列整合はUIが管理する。
ネイティブGUIの操作確認は自動テストとは別の受入確認として行う。

## TrainsWorld の一次コードとの対応

調査対象: TrainsWorld `6b8ef91729e1e5812f3dcbaedd6c0a49fed6a84b`。
TrainsWorld の `line` は Rosenfu の「系統」に近く、Rosenfu 固有の「路線」と同一視しない。
参照は挙動の確認のためで、コードを移植したものではない。

- `trainworld/sim/src/track/wasm/edits.rs:30–46`: `run` は可逆、`run_charged` は確定操作
- `track/world.rs:580–585`: 確定操作は履歴を消去、通常操作は逆操作を登録
- `wasm/lines.rs:13–17,119–165,489–538`: 系統作成・表示・複製・鉄道系統削除・運行設定は `run`
- `wasm/crossings.rs:380–398`: 建設済みホーム寸法変更は `run_charged`、駅名変更は `run`
- `wasm/links.rs:386–397,482`: 駅・線路削除は `run` のバッチ
- `wasm/links.rs:143–171`: 建設済み分岐の立体化、および着工は確定操作
- `wasm/links.rs:298–350`: 線種/線路数変更は計画線向け。建設済みの再開発と混同しない
- `wasm/rebuild.rs:1209–1231`: 既設線の高さ・線種・線路数再開発は `apply_priced(..., true, ...)` で確定
- `wasm/upgrades.rs:12–36`, `wasm/onetrack.rs:110–114`: 既設駅設備変更も確定

古いコメントの「undoable」「final」だけでは判断せず、実行経路を優先する。
