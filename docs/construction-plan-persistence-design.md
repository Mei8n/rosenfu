# 未着工線路計画の保存・復元設計（未実装・採用見送り）

2026-11-13のユーザー指示により、計画を再起動後まで残す実装は中止しました。
現在は同一セッション内の複数計画と任意の計画名を扱い、終了確認を維持します。
以下は撤回済みの調査記録であり、開発予定や実装済み仕様ではありません。現行保存は線路種別対応のschema 7ですが、計画の永続化は含みません。

調査基準: `46e2f5e`。この文書は設計であり、計画が保存可能になったことを意味しません。
この旧調査時点では未着工計画があると保存を無効にしていました。現行は未着工計画を画面に保持したまま、建設済みワールドを保存可能です。計画は保存されず、終了・読込時の破棄確認があります。

## 旧調査時点の制約（現行仕様ではない）

- `src/App.tsx` の計画はReact stateのみ。編集中1件と保持中の複数件で構成され、
  `points`、点Undo用`redo`、`curved`、UI内番号を持ちます。
- `line`は円弧生成結果のキャッシュです。入力点だけを将来の別アルゴリズムで再生成すると、
  同じ保存から違う線形ができる恐れがあります。
- schema 6の`SaveDocument`は`deny_unknown_fields`で`world`のみを保存します。
  `load_world`はWorldDraftだけを返し、成功時にUIが全計画を消去します。
- 保存先はセッション内で固定され、既存ファイルの初回上書きを防止します。
  更新時のバックアップと原子的置換はstorage側が担当します。
- 参考形状コピーには出典・選択元bundleの情報が必要です。手描き計画と混ぜて
  部分的に保存したように見せない必要があります。

## 撤回済みの第一段階案

手描き計画を、ワールドと**同じ保存ファイルの同じトランザクション**で保存します。
localStorageや独立sidecarに計画だけ置く方式は採りません。別のワールド読込時に
計画を誤って重ねたり、片方の保存だけ成功したりするためです。

### 保存形式

schema 7のトップレベルに`editor_plans`を追加し、World自体の建設済み設備とは分離します。
旧schema 1〜6の読込では明示的に空の計画集合へ移行します。旧アプリでschema 7を
開くと拒否される点を互換文書・リリース説明に記載します。

案:

```text
editor_plans:
  format_version: 1
  owner_company_id
  active_plan_id
  next_plan_id
  plans[]:
    id
    mode: straight | tangent_circle_v1
    control_points[]
    redo_points[]
    geometry_points[]
```

- UI番号はWorld内設備IDとは混ぜません。重複IDや不正なactive/next参照を拒否します。
- `geometry_points`は保存時の確定形状。読み込むだけで新しいアルゴリズムへ変換しません。
- `tangent_circle_v1`の再編集には同versionの生成器を用います。将来生成器を更新する際は
  version別生成器か、明示的な線形変換と確認が必要です。
- 始点1点だけ、Undo後に0点・Redoだけ残る状態も保存対象に含めます。
- タイル、hover位置、ドラッグ中状態、React callback、描画キャッシュは保存しません。
- first stageでは手描きのみ。参考形状コピーが進行中なら従来どおり保存を止めます。
  コピーの途中状態を黙って落として保存成功を表示しません。

### 検証と制限

Rustの読込境界で、有限座標、現編集範囲、会社参照、件数・点数・総容量、全IDを検証します。
上限は既存保存サイズと4096点/確定線形制限に合わせ、計画数と制御/Redo点の総量にも
明示的な上限を設けます。巨大入力で円弧再生成が暴走しない順序で検証します。

未着工なので「完成線路として不成立な途中状態」と「壊れた保存」は分けます。
半径不足や1点のみの編集中計画を勝手に削除せず復元し、着工の時点で再検証します。
曲線生成途中のエラーを保持する方式は、version付き制御点から再現できることをテストします。
不明なversionは読み飛ばさず、現在のセッションを変更せず拒否します。

### セッション/API

1. storageにWorld＋editor_plansを扱うsnapshot APIを追加。
   既存World専用APIが新保存の計画を無言で捨てないよう、明示エラーまたは
   plan-aware APIへの移行を行います。CLI・ヘッドレスも対象です。
2. `save_world`はUIの計画snapshotを受け取り、検証後にWorldと原子的保存。
   成功時だけ保存済み計画revisionを更新します。失敗時はUI/ディスク両方を保持。
3. `load_world`はWorld＋計画snapshotを返却。Worldと計画の両方を先に検証し、
   会社初期設定フラグ・loaded_pathを含むセッションの交換は最後にまとめて行います。
4. UIで通常の未適用編集（駅名・会社・路線・系統等）と保存可能な線路計画を分離。
   手描き計画だけなら保存を許可します。保存しても着工や費用支払いは行いません。
5. 未保存判定はWorldと計画の両方。保存成功後の終了で毎回破棄警告を出さず、
   点追加・Undo/Redo・計画切替・削除などの保存対象変更で再びdirtyにします。
6. 読込確認を拒否/読込失敗した場合は、編集中・保持中・Redoの全計画をそのまま保持。

## 実装前に固定すべき技術仕様

- 円弧生成v1をRust検証とTypeScript描画で一致させる方法。
  共通fixtureによる数値許容範囲を定め、保存と表示が変わらないことを確認する。
- World専用storage API/CLIがeditor metadataを落とさない契約。
- 参考コピー進行中の保存制限をUIで明示する。将来保存する場合は出典snapshotも含める。

これらを固定せずにstorage schemaだけ更新する変更は避けます。

## 必須回帰テスト

- schema 1〜6全fixtureを読み込み、既存設備を保持・計画空へ移行。
- 複数の離れた経路、直線/曲線、選択計画、Redoを保存→新プロセス読込し一致。
- 読込後のUndo/Redo・1本だけ着工・失敗・個別削除で他計画を維持。
- 保存前後の描画座標と着工payloadを一致。
- 未来形式、重複ID、NaN相当、不明生成器、範囲外、巨大件数を拒否し、既存セッションを保持。
- 容量不足・バックアップ失敗・置換失敗・初回既存保存拒否で元保存を保持。
- 保存後終了警告なし、保存失敗後/変更後は警告あり。
- 参考コピー/他未適用編集中は保存成功を表示しない。
- Windows実機で保存→終了→再起動→読込→再編集を検証。
