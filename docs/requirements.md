# 要件と設計方針

本書は2026年11月12日の機能要件まとめ Ver. 0.1をもとにした開発用の要約です。
「採用方針」は実装済みを意味しません。実装時期は[ロードマップ](roadmap.md)で管理します。

## 採用方針

- 日本全国を対象に、実在・架空の駅、線路、路線を自由に建設する。
- OSM等の実在駅を地図上の参考情報として表示し、ゲーム内駅と視覚的に区別する。ローカル参考駅パックの読込・表示切替・端末内保存は試作実装あり。実在駅からゲーム設備を自動生成するものではない。実OSMデータ・ネイティブ環境での確認とオフライン実地図の整備は別途必要（[参考駅パック](reference-station-packs.md)）。
- シングルと2〜5人程度のマルチでルールとシミュレーションを共通化する。原則1プレイヤー1会社とする。
- シングルプレイはオフライン動作可能にする。ネット接続がないことだけでゲームや既存ワールドを利用できなくなる設計を避ける。実地図の適法な事前入手・保存と未取得地域の扱いは[地図設計](map-backgrounds.md)で検討し、現段階で実装済みとは扱わない。
- 会社、路線、列車種別、運行系統を管理し、複数会社を乗り継げるネットワークを構成する。
- 需要はWork（通勤・通学）、Errands（日常生活）、Leisure（娯楽等）、Attractions（観光・集客施設）の4分類とする。
- 人口・目的地・曜日・時刻からOD需要を生成する。鉄道がない地域にも潜在需要を保持する。
- 流動は所要時間、待ち時間、乗換、運賃を総合評価し、競合する経路へ配分する。距離だけで列車種別を固定しない。
- 簡易ダイヤ、パターンダイヤ、将来の詳細ダイヤは共通の運行データを編集する。手動編集を自動生成で不用意に上書きしない。
- 平日・土休日、時間帯別、上下方向別に運行を設定する。仮の時間帯は5〜7時、7〜10時、10〜16時、16〜20時、20〜翌1時。境界は変更可能な構造とする。
- サーバーが共通の日付・時刻と計算を管理する。一時停止・速度変更は初期段階ではホスト権限とする。
- 運賃収入、運行経費、残高を扱う簡易経営と、資金制約のないサンドボックスを用意する。
- ゲーム内ホストと専用サーバーを用意する。無人時の進行はワールドオプションとし、保存・再開できるようにする。
- 需要・流動は全モードで有効とする。人口固定やサンドボックスでも停止しない。

## 追加要望と将来拡張

人口変動と非アクティブ時の資金保護は追加要望として扱う。
人口変動は交通利便性による長期的な増減を想定し、ON/OFFを選べるようにする。具体的なモデルは未定。
資金保護は非アクティブ・赤字・残高下限の条件で対象会社の残高の増減だけを凍結する。
凍結中も運行、需要、流動、人口、乗客数、計算上の収支は更新する。復帰条件や悪用防止は未定。

子会社、他社線直通、線路共用、詳細ダイヤ、バス連携、既存線路へのスナップは将来拡張・検討対象。
詳細ダイヤでは停車時間、待避、追越し、接続、折返し、単線交換、線路容量を扱う可能性がある。
初回正式版への採否はロードマップの提案と分けて判断する。

## 運賃設定の追加予定（2026-11-12）

会社の基本運賃を設定し、路線ごとに割増・割引率を設定できる機能を追加予定とする。
会社の基本運賃に対する路線別の倍率として扱う想定で、変更なしは 1.0 倍、割増・割引はその上下の倍率で表す。
これは将来機能の要件であり、運賃計算・設定画面・収入や経路選択への反映は未実装。

以下は未決定事項として、実装前に整理する。

- 基本運賃を均一制・距離制・区間制などのどの方式で算出するか。
- 割増・割引率の入力範囲、最低運賃、無料設定の可否。
- 端数処理の単位・方法と、倍率適用の前後どちらで丸めるか。
- 複数路線や複数会社をまたぐ乗車、乗換、重複する路線での適用範囲と計算順序。
- 運行系統と路線の対応、運賃変更を収入・旅客の経路選択へ反映するタイミング。

## 建設・駅運営・旅客選択・暦の追加要望（2026-11-12）

詳細と実装状況は[追加設計メモ](construction-and-service-planning.md)で管理する。次は採用方針・追加要望であり、実装済みではない。

- 通常・高速・トラムの線路種別、区間ごとのトラム併用/専用軌道、単線・複線・複々線、計画と着工・費用内訳を検討・実装対象にする。
- 駅は縮小時に点、拡大時に線形に沿う帯で表示し、駅長は20m級車両換算で扱えるようにする。駅長で建設費・維持費を変える。
- 駅運営形態（有人・無人・委託等）と駅の条件が維持費・満足度へ影響する。旅客は路線・駅の満足度、列車速度、出発地/目的地から駅への近さも考慮する。既存の時間・乗換・運賃の評価は維持する。
- 線路建設・路線・系統を分離する。路線の起終点を選ぶと中間駅を自動追加し、必要に応じて駅を除外する。その後、系統で路線上の出発・経由・終点を設定する。路線名と系統名は同一でも別名でもよく、各系統で各駅停車を基本に列車種別・停車駅を設定する。
- Escapeで選択モードから通常モードへ戻り、設置Undo/Redo、敷設中の地図ドラッグ、地名に基づく駅名候補と直接編集を用意する。
- 年は西暦でなく1年目・2年目と表示し、土日祝日は現行日本のカレンダーに従う。基準年、曜日・閏年、祝日改正の扱いは未決定。
- 時間加速は、参考ゲームの最大100倍でも遅く感じるという要望を踏まえて調整する。マルチ同期と計算負荷も考慮し、具体倍率・操作・負荷超過時の挙動は未決定。100倍をRosenfuの確定上限として扱わない。

- 線路規格・カーブ等による速度上限と手動速度制限を扱い、低速時は車両維持整備費を軽く、高速時は重くする。120〜130km/h以上という目安は確定閾値ではない。
- 定員、材質による重量・運行費・修繕費、省エネ制御、特急車内設備と満足度を扱う簡易車両設計を用意し、系統の列車種別ごとに使用車両を指定する。
- UIのライト／ダーク、線太さ、地図コントラスト、パネル・文字サイズを調整可能にする。
- 費用は2000〜2020年代を参考に、現実よりやや安めで遊びやすいバランスとする。基準年・具体額・調整率は未決定で、価格調査済みではない。

参考ゲームの7段階の高さ・自動乗越・各種追従補助・駅改良例は、採用確定値と分けて追加設計メモに記録する。参考の駅長範囲・維持費をそのまま採用しない。

## 設計上の分離

- 画面とシミュレーション。シングルでも同じエンジンを使う。
- 人口、需要生成、流動計算、経営と資金の更新。
- プレイヤー、会社、駅、線路設備、路線、運行系統、列車種別。
- ダイヤの生成規則、生成された運行、手動で変更した内容。
- 永続データと再計算可能なキャッシュ。

線路設備と運行系統の分離は、将来の共用や直通を可能にするための設計提案。
将来機能のためだけに空のテーブルを大量に作ることは求めない。
