# 要件と設計方針

本書は2026年11月12日の機能要件まとめ Ver. 0.1をもとにした開発用の要約です。
「採用方針」は実装済みを意味しません。実装時期は[ロードマップ](roadmap.md)で管理します。

## 採用方針

- 日本全国を対象に、実在・架空の駅、線路、路線を自由に建設する。
- シングルと2〜5人程度のマルチでルールとシミュレーションを共通化する。原則1プレイヤー1会社とする。
- 会社、路線、列車種別、運行系統を管理し、複数会社を乗り継げるネットワークを構成する。
- 需要はWork（通勤・通学）、Errands（日常生活）、Leisure（娯楽等）、Attractions（観光・集客施設）の4分類とする。
- 人口・目的地・曜日・時刻からOD需要を生成する。鉄道がない地域にも潜在需要を保持する。
- 流動は所要時間、待ち時間、乗換、運賃を総合評価し、競合する経路へ配分する。距離だけで列車種別を固定しない。
- 簡易ダイヤ、パターンダイヤ、将来の詳細ダイヤは共通の運行データを編集する。手動編集を自動生成で不用意に上書きしない。
- 平日・土休日、時間帯別、上下方向別に運行を設定する。仮の時間帯は5〜7時、7〜10時、10〜16時、16〜20時、20〜翌1時。境界は変更可能な構造とする。
- サーバーが共通の日付・時刻と計算を管理する。一時停止・速度変更は初期段階ではホスト権限とする。
- 運賃収入、運行経費、残高を扱う簡易経営と、資金制約のないサンドボックスを用意する。
- ゲーム内ホストと専用サーバーを用意する。無人時の進行はワールドオプションとし、保存・再開できるようにする。
- 需要・流動は全モードで有効とする。人口固定やサンドボックスでも停止しない。

## 追加要望と将来拡張

人口変動と非アクティブ時の資金保護は追加要望として扱う。
人口変動は交通利便性による長期的な増減を想定し、ON/OFFを選べるようにする。具体的なモデルは未定。
資金保護は非アクティブ・赤字・残高下限の条件で対象会社の残高の増減だけを凍結する。
凍結中も運行、需要、流動、人口、乗客数、計算上の収支は更新する。復帰条件や悪用防止は未定。

子会社、他社線直通、線路共用、詳細ダイヤ、バス連携、既存線路へのスナップは将来拡張・検討対象。
詳細ダイヤでは停車時間、待避、追越し、接続、折返し、単線交換、線路容量を扱う可能性がある。
初回正式版への採否はロードマップの提案と分けて判断する。

## 設計上の分離

- 画面とシミュレーション。シングルでも同じエンジンを使う。
- 人口、需要生成、流動計算、経営と資金の更新。
- プレイヤー、会社、駅、線路設備、路線、運行系統、列車種別。
- ダイヤの生成規則、生成された運行、手動で変更した内容。
- 永続データと再計算可能なキャッシュ。

線路設備と運行系統の分離は、将来の共用や直通を可能にするための設計提案。
将来機能のためだけに空のテーブルを大量に作ることは求めない。
