# ワールドデータ互換方針

## 保証の範囲

最初のベータ版（予定: `0.6.0-beta.1`）で作成したワールドから、後の版へ引き継げることを基本方針とします。
古いワールドを新しいゲームが読み込む方向の保証です。新しい版で保存したワールドを古いゲームで開くことは保証しません。
アルファのワールドは保証対象外ですが、移行可能なら手段を提供します。リセットが必要な版は配布時に明記します。

引き継ぐ対象は会社・所有権、駅・線路・路線、運行系統・編集済みダイヤ、日付、人口、資金、設定などの永続状態です。
流動キャッシュ等の再生成可能なデータは再計算できます。モデル改良による利用者数・収益の変化は形式互換とは分けて説明します。
ワールドを開けても設備や手動編集が失われる移行は成功とみなしません。

## ベータ前に整える基盤

1. 安定した識別子と参照整合性を設ける。プレイヤーと会社、設備と運行を分離する。
2. 共通時計に日付と日跨ぎを保持する。時刻の表現・暦・休業時間の扱いを決定する。
3. 人口、需要、流動、経営を分離し、無効化オプションの意味を保存する。
4. 自動生成ダイヤと手動変更の対応を保持し、再生成時の保護・競合解決を決定する。
5. 形式番号、作成・最終保存ゲーム版、使用データセットを識別できるメタデータを持たせる。
6. 保存・読み込み・移行を画面から独立させ、ヘッドレスで検証できるようにする。

子会社のない会社へ親会社参照を追加する、固定人口へ変動状態を追加する、鉄道だけの運行へ交通手段を追加する、といった模擬移行をアルファ中に試します。
既存データへの既定値と変換規則を検証するための試験であり、将来機能の採用や具体的な保存形式を確定するものではありません。

## 読み込みと移行

1. 形式番号と対応範囲を確認する。未来の形式や破損データは変更せず、理由を表示して読み込みを拒否する。
2. 移行前に、一貫した状態の元ワールドを別ファイルへバックアップする。バックアップ失敗時は移行しない。
3. 作業コピー上で旧形式から順に移行する。外部キー、所有権、ダイヤ、金額、日付などを検証する。
4. 成功を確認してから安全に保存先へ切り替える。途中終了時は元データまたはバックアップから復旧できるようにする。
5. 完了した形式とバックアップの場所を通知する。失敗時は元データを残し、診断情報と復旧方法を案内する。

保存方式がSQLiteとなる場合、稼働中のDBファイルだけを単純コピーする実装は避け、一貫したスナップショットを取得する方法を選びます。
書き込みの排他、容量不足、バックアップの保存場所・世代数は実装時に決定します。移行中はサーバーからの書き込みも停止します。

## 継続的な検証

各公開ベータの代表ワールドをテスト資産として保持し、各新版への直接読み込みと連続移行を自動検証します。
試験資産は再配布できる合成データ等を使い、個人情報や配布不可の地図・統計データを含めません。

- 空ワールド、複数会社、日跨ぎダイヤ、手動編集、資金凍結、人口固定などの状態を含める。
- 移行後の参照関係と永続状態、保存・再読込を確認する。
- 同じ移行済みデータの再読み込みで二重変換しないことを確認する。
- 破損、未来形式、容量不足、処理中断、バックアップからの復旧を確認する。
- シングル・ゲーム内ホスト・専用サーバー間で同じ結果を読み込めることを確認する。

互換性を壊す不具合はリリースを止める対象です。維持できない例外は事前に理由と影響を公開し、可能な限り変換ツールや旧版での復旧手段を提供します。
例外を通常の更新手順にせず、既存ワールドを黙って初期化することは禁止します。
