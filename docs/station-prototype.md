# 小地域・駅配置と線路接続の縦切り試作

## 目的と範囲

駅を配置すると Rust 側のワールドが更新され、保存・再読込でも同じ駅と ID が
維持される経路を、デスクトップ画面から確認するための試作です。
実地図はオンライン背景を任意選択し、移動とズームができます。列車運行、旅客需要・流動は未実装です。線路は駅間の直線接続に限定します。

初期背景は本プロジェクトで作成した抽象的な SVG グリッドです。
背景選択から国土地理院の淡色地図をオンライン表示できます。画像は同梱しません。
編集範囲は緯度20〜46、経度122〜154です。初期表示は東京周辺で、カメラとワールド座標は分離します。
座標の画面変換は Web Mercator です。距離や面積の計測には使用しません。
利用条件・出典・表示方式は[実地図背景](map-backgrounds.md)を参照してください。

## 操作

1. `npm run tauri -- dev` でデスクトップ版を起動します。
2. 駅タブで「駅配置」を選び、駅名を入力して背景上をクリックします。初期の「移動」モードでは駅を配置しません。
3. 駅一覧と描画位置を確認し、2駅を選択して線路で接続します。
4. 保存し、再起動後に読み込むと駅・線路が復元されることを確認します。

新規セッションにはプレイヤー1人と鉄道会社1社が存在します。
配置操作は Tauri コマンドを通して Rust に送信し、コアが ID を採番します。
フロント側では ID を数値へ変換せず、成功したワールドだけを画面に反映します。
ブラウザ起動は表示プレビューのみで、配置・保存・読込は実行しません。

## 保存先と保護

保存先は Tauri のアプリ専用データディレクトリ内の
`prototype/world.rosenfu.json` に固定しています。任意のファイルパスは UI から受け取りません。
保存先ディレクトリは保存時に作成します。テストは一時ディレクトリのみを使います。

新規セッションが既存ファイルへ保存しようとした場合は拒否し、先に読み込むよう案内します。
読込済み、または新規保存に成功したセッションの更新は前回データを `.bak` に残します。
破損・未知版・この画面で扱えないワールドの読込に失敗しても、編集中のデータを変更しません。
この画面ではプレイヤー1人・会社1社・編集範囲内の駅を持つワールドだけを読み込めます。

## 外部データへの移行前に確認すること

- OSM 標準タイルの一括取得・オフライン同梱を前提にしない。
- 地理背景、人口データ、プレイヤーが作成する駅・線路を分離する。
- e-Stat、国土数値情報 N02 などは対象データごとの利用・再配布条件と帰属表示を確認する。
- 全国表示やオフライン対応の前に描画・配布方式を再検証する。

オンライン背景の採用は外部データのオフライン同梱許諾を意味しません。MapLibre もまだ導入していません。
GUI 実機表示の検証は、画面操作接続が利用できる環境で別途実施する必要があります。

## 駅間の線路接続

接続元と接続先の2駅を選んで線路を追加できます。端点を参照する Track を
Rust 側で採番・作成し、画面では駅間を結ぶ直線として表示します。
駅と同じワールド保存に含まれるため、再読込後も端点・ID・接続関係を維持します。

- 同じ駅への接続、存在しない駅、同じ2駅間の重複接続を拒否します。
- 向きを入れ替えても同じ接続と扱います。現段階は双方向の接続です。
- 拒否された操作はワールドと採番カウンターを変更しません。
- 線が交差しても自動的に分岐・接続を作りません。接続するのは明示した端点だけです。
- 直線は接続の可視化であり、実際の線形・延長・勾配・建設費の計算ではありません。
- 曲線編集、線路途中への駅追加、分岐、単複線、待避、線路容量は未実装です。未参照設備の削除は後述の安全編集に対応し、操作単位の取り消しは未実装です。
- 複数線路を束ねる路線は後述の暫定UIで編集できます。運行系統、ダイヤ・旅客流動は後続です。

同一駅間の重複拒否はこの試作画面の誤操作防止です。将来の複線・並行設備の
モデルを禁止する仕様ではなく、共通コアの設備表現とは分けて扱います。

## 会社名と路線の作成・編集

新規セッションの開始時にプレイヤー1人・鉄道会社1社を作成します。
会社の設定画面では会社名を変更できます。ID・所有者・既存の駅や線路は変更しません。
同じプレイヤーによる追加会社の設立や子会社関係は、この試作では提供しません。

路線は名称・起点駅・順序付きの線路 ID 列を持つ独立したデータです。
起点駅から接続を辿れる順に線路を選び、1本以上の線路を含む路線を作成します。
既存路線は同じ ID のまま名称・起点・線路列を変更できます。変更しても設備自体や
他の路線のデータは変更しません。同じ線路設備を複数の路線から参照できます。

- 存在しない駅や線路、接続順の不整合、空の線路列は拒否します。
- 作成・編集に失敗した場合、ワールドと採番状態を変更しません。
- 既存路線の編集では新しい ID を消費しません。
- 路線の保存は他のワールドデータと同じファイルに含まれます。Route フィールドは
  スキーマ1から継続しています。現行スキーマ2では独立した運行系統を追加し、旧版を移行します。
- 環状の経路や同じ設備の再使用はコアで禁止しませんが、実際の運転可否は判定しません。
- 路線削除、会社追加、列車種別・ダイヤは未実装です。運行系統・停車位置は系統タブで編集できます。運行系統のコアと保存は[基本構造](operating-services.md)を参照してください。

路線は運行系統ではありません。この画面で路線を作成しても列車は走らず、
停車駅や運行本数も設定されません。設備・路線・運行系統の境界を維持して拡張します。

現在の路線編集は1本の連続経路を扱う暫定UIです。分岐を含む路線の設備集合や、
それを複数の運行系統が走る場合の表現は未確定です。現在の線路列を将来の運行系統の
データとして流用すると決めたものではなく、ベータ前の設計検証で見直します。

## 駅名変更と未参照設備の削除

駅を選択して名称を変更できます。駅ID・緯度経度・線路・路線・系統の参照は変更しません。名前の下書きはワールドへの適用とファイル保存を分け、未適用のまま別駅選択やワールド読込で失われないよう確認します。

駅の削除は、接続線路や路線・系統から参照されていない場合だけ可能です。線路の削除は、路線・系統から参照されていない場合だけ可能です。参照理由を画面に表示し、実行前に確認します。バックエンドも参照を再検証し、拒否時はワールドと採番を変更しません。連鎖削除はしません。

路線・系統などの未適用下書きがある間は削除できません。先に適用または破棄してください。削除後も採番器を巻き戻さず、削除したIDを再利用しません。ファイルに反映するには通常の保存が必要です。操作単位のUndo、駅移動、路線・系統自体の削除は未実装です。

確認手順: 未参照線路を削除し、孤立した駅を削除する。路線または系統が使用する線路は削除できないことを確認する。駅名変更後に既存の接続・系統が保持され、保存再読込で同じIDを復元することを確認する。削除確認のキャンセル、処理失敗、連打、未適用下書きの保護も確認する。必ず専用の試験ワールドを使う。

## 駅設置 UI の簡略化（2026-11-13）

- 設置前の駅名入力は不要。ローカル参照駅パックの半径1km以内・最寄りの有効名を仮名として自動採用。候補なしでは「新駅」、同名の場合は番号を付ける。設置後の改名は維持。
- 町名・住所の逆ジオコーディングと実在駅データの自動ダウンロードは未実装。背景画像から名前を読み出すものではない。近傍の参考駅と同一駅、または正式名称とは限らない。参照パックの手動導入後はオフラインで動く。
- ホーム長の入力は20m級・両相当のみ。内部メートル保存、小数は丸めない。従来の20〜1000m制約に対応する1〜50両相当。実車収容判定ではない。
- 幅入力を非表示。新規は従来の12m、既存駅は保存されている幅を維持。
- 操作エラーは5秒後に消え、×でも閉じられる。新しい通知（同文再通知も含む）は再計時する。閉じても失敗が成功扱いにはならない。モード変更や正しい位置の再選択でも過去のエラーを消去。

## 設置後の駅設定編集（2026-11-13）

駅管理タブまたは地図の駅選択から、駅名とホーム長を後で変更できる。ホーム長は20m級両相当で編集し、既存の幅・所属線形・位置・駅IDは維持する。未変更・範囲外の適用は抑止。名前だけでなくホーム長の下書きも保存・終了・駅切替時の保護対象とし、個別に破棄できる。適用失敗時は入力を保持し再試行できる。変更はワールド適用後、通常保存でファイルへ反映する。

有人・無人・委託の運営形態、設備改良、維持費・満足度との連動は追加予定で未実装。将来これらも設置後に編集できる構成を必須とする。現段階で設定や経済効果があるようには表示しない。
