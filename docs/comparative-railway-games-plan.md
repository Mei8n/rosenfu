# 空想鉄道・A列車の比較から得た設計補強案

調査整理日: 2026-11-13。対象: 復元版 `502ab51`。

本書は未実装機能の一時設計資料。公式記述、利用者の個別意見、Rosenfu向け提案を区別する。実装・検証後は確定した仕様と根拠を恒久資料に移し、本書を削除する。参考作品の仕様をそのまま採用する決定ではない。

## 現行実装と既定方針

現行は建設、路線・系統、保存基盤を中心に実装中。需要生成・流動・都市発展の実装済みという意味ではない。復元資料には古い「未実装」表もあるため、個々の機能状態はコードとテストで確認する。

- 物理線路、路線、系統、種別を分離する。線形を描く点と駅を同一視しない。
- 地図上の構想を、運行・流動を伴う架空鉄道として動かすのが中心。資源取引や不動産経営を建設の必須前提にしない。
- 人口、潜在需要、経路配分、実輸送、収支を分離。人口固定でも需要・流動は計算する。
- 人口変動は任意かつ低頻度。全国規模と少人数マルチの負荷を優先する。
- **最新指示では未着工計画はタブ移動で消さず、セッション終了時に破棄する。終了前に警告する。** 手動保存・自動保存の対象である建設済みワールドとは寿命を分ける。過去の「計画保存」案を復活させない。
- 日本向け運賃は[運賃案](japan-fare-model-notes.md)と整合させる。駅間直線距離のみの運賃へ置き換えない。

## 1. 空想鉄道: 構想の編集と表現

### 公式に確認された操作

[公式サイト・操作説明](https://ku-tetsu.net/)には、クリックで線を描く、点をドラッグして修正、中間マーカーから点追加、逆向きへの延伸、点の駅化、複数選択、曲線プレビュー、編集ロック、路線コピー・統合、色・幅・駅名ラベル位置の調整、地名入力支援がある。

Rosenfuの「描く→駅を置く→名前や属性を調整」に合う。一方、空想鉄道が旅客需要や経営をシミュレートする根拠は今回確認できていない。[空想別館](https://annex.chi-zu.net/)、妄想鉄道アプリ、空想路線図は別サービスとして扱う。

### 利用者の個別意見・利用例

- [2016年の作者ブログ](https://okakyu.seesaa.net/article/434850810.html): ブラウザで使え、ブログへ埋め込める点を評価。現在の利用者多数派の意見とはしない。
- [公式掲示板の2022年要望・運営回答](https://old.ku-tetsu.net/fstyletemp/read_old.php?key=1634360234&st=276&to=286): 車両作成・走行への要望、保存や重さ、ロックに関する案内。当時の報告であり現行不具合とは断定しない。
- [「マイカーが無い世界」制作例](https://note.com/youtopia_diary/n/nfe9226f0255c): 世界の前提を変えて会社・本線・支線・直通を構想する一次例。評価の統計ではない。
- [簡易路線図ジェネレータ](https://rosenzu.app/): 空想鉄道インポート、種別・乗換・ナンバリング、画像と編集データ出力に対応する関連ツール。空想鉄道本体の機能と混同しない。

### Rosenfuへの提案

近い建設UI段階では、計画の再編集、計画ごとの表示切替・誤編集防止ロック、選択対象とスナップ先の明示、ラベル衝突回避を検討する。名前や規格の入力を必須にせず、まず描けることを優先する。Undo/Redoと保存状態表示は既存要望を継続する。

将来候補は計画案の複製・比較、任意の低解像度車両アイコン、系統・種別に基づく案内路線図出力。地理的線形と案内図レイアウトは別管理。複製で設備・所有権・収支を二重化しない。公開作品の取り込みは権利者の許諾・公開条件を確認する。

匿名投稿や更新キーの仕組みは移植しない。身内マルチの所有権・編集権限と整合させる。曲線編集の自由度のために円弧や勾配の妥当性チェックを外さない。

## 2. A列車: 旅客と沿線発展の因果を見せる

### 作品別の公式仕様

- **Exp.（A9系）**: [都市開発のヒント](https://www.artdink.co.jp/manual/aexp/about02/about02.html)は人の流れ・資材・電力、沿線施設と発展の循環、バスの補完、本数・編成の調整を説明。駅を置くだけで無条件に人口増加するという根拠ではない。
- **はじまる観光計画**: [旅客](https://www.artdink.co.jp/manual/a-tourism/switch/ja/hint/01.html)は出発駅と行先駅の発展、建物用途と時間帯、運賃による公共交通利用率への影響を説明。運賃が駅間直線距離基準という点はRosenfuには適用しない。
- 同作の[都市開発](https://www.artdink.co.jp/manual/a-tourism/switch/ja/hint/03.html)は駅利用者、観光地周辺施設、隣街・空港との接続を説明。最大4観光名所の制限は作品固有。
- 同作の[観光案内](https://www.artdink.co.jp/manual/a-tourism/switch/ja/main/13-02.html)は経路表示、未接続・輸送不足の警告を提供。徒歩乗換候補を近い4箇所に絞る制限をそのまま持ち込まない。
- [産業統計](https://www.artdink.co.jp/manual/a-tourism/switch/ja/main/13-03.html)には産業別表示・公共交通利用率がある。
- **A9 PRIME LINE**: [製品概要](https://www.atrain.jp/title/a9pl/product.html)では2026年12月10日発売予定。調査日時点は未発売なので旧作のレビューと混ぜない。

### 利用者の個別評価と限界

- [みんなのA列車PCのSteamレビュー](https://steamcommunity.com/app/492090/reviews/?browsefilter=toprated&l=japanese&p=1): 路線から街が育つ体験やバスの補完を評価する声と、鉄道より資源・子会社経営が先になる不満。UIの細かさにも言及がある。
- [価格.comの個別レビュー](https://review.kakaku.com/review/K0000919278/ReviewCD%3D1007321/): UI・操作に関する評価。後年の改善言及もあり、古い不満を未修正の現状として扱わない。
- [A9](https://www.4gamer.net/games/101/G010184/index_userreview.html)・[Version3](https://m2.4gamer.net/games/256/G025694/index_userreview.html): 景観・運行自由度への評価、目的地の納得感・個別ダイヤ・時間スケールへの不満。古い作品の「次駅で全員降りる」という意見をシリーズ全体の仕様に一般化しない。
- [はじまる観光計画のSteamレビュー](https://steamcommunity.com/app/1685460/positivereviews/?browsefilter=toprated&l=japanese): 観光動線や自由度への評価、経路設定・資源契約管理、自動発展の強さへの意見。肯定レビューを抽出したページであり、支持率や多数派の推定には使えない。
- [公式更新履歴](https://www.artdink.co.jp/japanese/title/a-tourism/update/)には乗換候補表示、複写・一括曜日変更、警告等の改善。更新前の不具合と現行仕様を分ける。

レビューは代表的な個別意見として読む。投稿時の作品・版を尊重し、網羅性や多数派、レビューだけからの内部アルゴリズム確定を主張しない。今回は実機での再現試験をしていない。

## 3. 需要・流動の補強設計（未実装案）

[TrainsWorld調査との照合](trainsworld-findings-integration-audit.md)と既定の4分類需要を維持し、次を設計に含める。

1. 発地人口だけでなく目的地用途・雇用・集客力を扱う。住宅→工業地域の朝流入、逆方向の夕流出を区別。昼間の工業地域を一律に高需要としない。
2. 潜在OD需要、公共交通選択、乗れた人数、積み残しを別集計する。人口と旅客人数を二重に加算しない。
3. 駅や路線の診断では経路なし、アクセス不便、運賃、待ち時間、混雑・容量不足のどこが利用を妨げるかを示す。推定理由を因果実験済みの事実として表示しない。
4. 空港・観光施設の魅力と交通到達可能性を分離。周辺人口が少ないことだけで需要をゼロにしない。実在鉄道駅の存在自体を初期需要の目的地にしない。
5. 沿線発展は土地容量・産業構成・変化率上限・便益の逓減を持つ低頻度の地域集約更新。増発→人口増→増発の無限成長を防ぎ、人口固定でも経路再配分を行う。
6. シングルとマルチで計算規則を共通にし、重い需要更新と地図操作を分離する。用途・時間帯の集約、変更地域だけの再計算を検討する。全国の個人全員を毎フレーム探索しない。

開発停止・低成長地域、自家用車競争強度や需要倍率は将来のワールド設定候補。採用済みの人口変動ON/OFFと区別し、数値やUIを今回確定しない。資材・電力・株式・詳細財務は必須に追加しない。

## 4. 段階と受入試験

[ロードマップ](roadmap.md)の目安に対応し、今回の日程・版の確約はしない。

| 段階目安 | 対象 | 実装時の確認 |
| --- | --- | --- |
| 建設UI改善 | 計画編集・ロック・スナップ表示 | 無名で描ける。ロック理由が分かる。タブ移動で計画維持、終了警告の取消で維持、終了で破棄 |
| 0.2 基礎流動 | 潜在OD・経路・輸送の分離 | 鉄道なしでも潜在需要があり、開業・増発で配分が変化。乗客を次駅で無条件に降ろさない |
| 0.3 時間帯・分析 | 用途別ODと診断 | 工業地域の朝夕方向差、観光休日、空港アクセスを比較。高運賃・接続切れ・容量不足を別々に作って識別 |
| 人口変動導入時 | 低頻度の沿線発展 | OFFで人口不変・流動変化、ONでも成長上限と時間尺度を守る。駅数を増やして全地域総当たりにならないか測定 |
| マルチ導入時 | 共通計算と更新配信 | 同条件でシングルとホスト結果一致。途中参加や再接続で需要・収入を二重計上しない |

性能は小地域から駅数・OD数を段階的に増やし、計算時間、メモリ、地図入力遅延を測定して予算を決める。近い4駅等の固定打ち切りで必要な経路を無説明に消すのではなく、近似・候補削減の誤差を検証する。

本書追加のみでは上記機能の実装・性能確認は完了しない。恒久要件へ昇格する際は、採用した項目、未採用理由、検証結果を残す。
