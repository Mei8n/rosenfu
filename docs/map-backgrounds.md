# 実地図背景の技術検証

確認日: 2026-11-12

## 今回採用する表示経路

国土地理院の「淡色地図」ZL12〜16 を、利用者がオンライン背景を選んだ間だけ読み込みます。
既定は従来の自作サンプル背景です。実地図はカメラ周辺の表示に限り、表示外の全国取得は実装しません。MapLibre の正式採用やオフライン配布方式の決定ではありません。

- 編集範囲: 北緯20〜46度、東経122〜154度。日本を含む矩形であり国境や地図提供範囲を示さない。初期カメラは東京。
- URL: `https://cyberjapandata.gsi.go.jp/xyz/pale/{z}/{x}/{y}.png`
- ズーム: 12〜16。画面と交差するタイルだけを選択し、上限20枚とする。
- 取得: SVG の画像表示による通常のオンライン読み込み。独自の先読み・一括取得・
  オフラインキャッシュ・Service Worker は使用しない。通常のブラウザHTTPキャッシュは別。
- 画像をリポジトリ・パッケージ・ワールド保存に含めない。
- 読み込みの失敗を明示し、自作背景へ戻せる。失敗時に偽の地図へ黙って差し替えない。

## 利用条件と出典

[地理院タイル一覧](https://maps.gsi.go.jp/development/ichiran.html) のリアルタイム読込の案内と、
同ページの日本向け淡色地図 ZL12〜13、14、15〜17 の項目を確認しました。アプリでのオンライン表示は、
同案内に従い出典と一覧へのリンクを表示する方式に限定しています。

[国土地理院コンテンツ利用規約](https://www.gsi.go.jp/kikakuchousei/kikakuchousei40182.html) は
[公共データ利用規約 PDL1.0](https://www.digital.go.jp/resources/open_data/public_data_license_v1.0) と
サイト固有情報を参照しています。表示には出典を付け、加工とその主体を別途明示します。

画面の帰属表示は「出典: 国土地理院 地理院タイル（淡色地図）」と一覧ページへのリンクです。
表示範囲の切取・拡縮と架空の駅・線路の重畳を Rosenfu が行ったことを示し、
架空設備を国土地理院の情報と誤認させない表示にします。
オフライン複製・再配布の許諾をこの確認で得たとは扱いません。配布方法を変える前に再確認します。

## 加工と座標の取り扱い

[公式タイル仕様](https://maps.gsi.go.jp/development/siyou.html) に合わせ、XYZタイルと
Web Mercator の変換を用います。`src/map.ts` が編集範囲、カメラ、投影、逆変換とタイル列挙を管理します。
地図の縦横比を維持したまま画面全体を埋めます（SVG の xMidYMid slice）。画面外へはみ出す部分を中央基準で切り取り、クリック座標・ドラッグ倍率・表示範囲も同じ計算を使用します。画面外のクリックは受け付けません。
端のタイルを表示範囲でクリップし、プレイヤー設備は別のベクター層として重ねます。

保存済みの緯度・経度や ID は変換・書き換えません。背景切替は表示設定だけです。
従来の線形表示から投影を変更するため、画面内の見え方は少し変化します。
国内タイルのJGD2011とWGS84の厳密な測地系変換や測量精度は保証しません。
距離計算・現地ナビゲーション・設計測量には使わないでください。

背景、人口・需要の入力、プレイヤーが作る駅・線路は独立したデータとして扱います。
タイルに描かれた実在駅や線路を、ゲーム内設備として自動生成することはありません。
人口データ、e-Stat、国土数値情報N02の同梱はこの変更には含みません。

## 検証と制限

- 投影と逆変換、横長・縦長画面の端部クリックと画面外クリック、タイル上限と配信先を単体テストする。
- UIテストはネット接続に依存せず、ロード/エラーイベントを模擬する。
- 代表タイル `12/3636/1611` は確認日にHTTP 200、PNGとして取得できることを確認。
- 分離したローカル Edge のブラウザプレビューで、初期画像要求なし、東京の16枚、拡大後20枚、大阪への移動後20枚の計56応答すべてHTTP 200、地図の表示と駅座標の不変を確認。ネイティブ WebView の実操作は未確認。
- CSPでは画像に限り `https://cyberjapandata.gsi.go.jp` を許可する。任意の配信URLを受け取らない。
- OSM標準タイルは使用しない。[同タイルの利用方針](https://operations.osmfoundation.org/policies/tiles/) に
  反する一括取得やオフライン同梱を行わない。
- オンライン提供の継続や更新時点は保証しない。正式配布・広域対応の前に
  配信負荷、利用条件、更新管理、オフライン方式を別途設計する。

## 地図移動・ズームの検証段階

画面のカメラはワールドから独立します。移動や倍率変更は保存済み駅の緯度経度、ID、線路接続を変更しません。カメラは保存データに追加しません。旧版の東京ワールドも[保存基盤](storage.md)の移行経路で読み込めます。旧アプリで新しいワールドを開くことは保証しません。

方向ボタン、中心座標指定、ドラッグ、ホイールで移動・拡縮できます。慣性移動、地名検索、全国俯瞰、巨大ネットワークの描画最適化は対象外です。サンプル背景はカメラと連動する連続パターンの抽象図です。道路・河川は実際の地理とは対応しません。有限の絵の端が画面内で途切れることを避けるため、背景を繰り返して表示します。

要求は対話的な表示に限定し、連続操作は250msのデバウンスで間引きます。通常のHTTPキャッシュを利用し、独自の無期限キャッシュ・一括ダウンロード・先読み・自動再試行は追加しません。矩形内でも海上や配信範囲外ではタイルがない場合があり、失敗を明示します。

## 手動受入確認

1. デスクトップ版を起動し、初期サンプル表示を確認する。オンラインを選ぶまでは地図画像を要求しない。
2. オンライン背景を選び、出典と加工表示、読込状況を確認する。
3. 方向ボタン、拡大・縮小、中心座標指定で移動する。大阪・札幌・那覇の各地域で確認する。
4. 移動前後に駅を配置し、線路・路線を設定する。ボタン操作だけでは駅が追加されないことを確認する。
5. 駅の緯度経度・IDを控え、倍率変更・背景切替・保存・再起動・再読込の後も値と接続が同じことを確認する。カメラ自体は保存されず初期表示へ戻る。
6. ネットワークがない環境で失敗表示とサンプル背景への復帰を確認する。失敗した背景を正常な実地図と誤認させない。
7. 旧版で作成した東京範囲のワールドのコピーを読み込み、駅と線路を確認する。本番の唯一の保存をテストに使わない。

この手順は受入項目であり、すべてのネイティブ実機検証が完了したことを意味しない。

## 移動と配置の誤操作防止

初期モードは「移動」です。駅を地図クリックで建設する時だけ、駅タブで「駅配置」を選択します。座標を直接入力して配置する既存フォームは別操作として残します。別の編集タブへ移ると移動モードに戻ります。

どちらのモードでも、5px以上動かすドラッグは地図移動として扱い、直後のクリックでは駅を建設しません。ポインターのキャンセル時も建設しません。移動・拡縮はワールド編集ではなく、未保存状態やIDを変えません。

手動検証では、移動モードのクリック、駅配置モードのクリック、ドラッグ直後、地図外でのボタン解放、タブ切替、ホイール連続入力をそれぞれ確認してください。地図外の通常スクロールを妨げないことも確認します。

操作回帰は38件のフロントテストに含めています。分離Edgeの実ポインター入力と模擬エンジンで、移動クリック・既存駅クリック・ドラッグ・途中モード変更が駅追加を引き起こさず、明示配置だけ追加することを確認しました。地図内ホイールと地図外スクロールの分離も確認しています。模擬エンジンは実保存を使わず、ネイティブWebViewの受入確認とは区別します。

ホイールは中心基準の段階ズームで120msの上限頻度を設け、ドラッグ中は倍率を変更しません。修飾キー付きホイールには介入しません。慣性・タッチピンチは未実装で、タッチ/ペン実機は未検証です。

## 地理データの保存方式の比較検討（2026-11-12、未決定）

共同開発者から「地理情報をリレーショナルに保存しておくメリットはある」との意見が共有された。これは検討の入力であり、SQLite 等の採用決定や性能検証の結果ではない。現在の表示タイル方式とワールド JSON 保存を、この追記で変更するものではない。

### 表示と意味のある地理情報を分ける

- 背景表示用のラスター／ベクトルタイルと、敷設補助に使う道路・鉄道の形状、接続関係、属性は別の役割。画像タイルから接続グラフを直接得られるとはみなさない。
- OSM の道路・鉄道を追従する場合は node / way / relation、元ID、形状、タグ、取得時点・出典を保持する候補を検討する。レンダリング向けに簡略化・分割された形状だけでは追従や接続判定に不足する可能性がある。
- 形状が交差するだけで接続とは判断しない。橋梁・トンネル・高さ等の属性と元データの接続関係を調べ、誤りや欠落への対応を決める。
- 参照用の実在地理データと、プレイヤーの駅・線路・計画・運行経路は分離する。参照地図の更新が建設済み設備を暗黙に移動・削除しないようにする。

### 候補と評価観点

以下は技術的な比較候補であり、Rosenfu 上での実装・ベンチマークは未実施。

| 候補 | 検討する利点 | 注意点・比較する負担 |
| --- | --- | --- |
| SQLite + 通常のリレーショナル表 + R-tree 等の空間索引 | 地物・属性・参照関係の結合、地域別単一ファイル配布、トランザクション更新、近傍候補の絞り込みを一体で管理しやすい | R-tree は候補抽出であり、正確な線への投影や経路探索は別処理。必要な拡張のビルド対応、索引構築時間、容量、単一writer前提の更新を確認 |
| SQLite + 空間拡張（SpatiaLite 等） | 空間型・空間演算を利用できる候補 | ネイティブ依存、3 OSへの配布、Rust連携、拡張バージョンと再現性、必要な演算だけで十分かを比較 |
| GeoPackage 等の地理情報交換形式 | SQLite ベースの標準化された地物保存と既存 GIS ツールとの交換 | 道路・鉄道のトポロジーやゲーム用グラフが自動で揃うわけではない。スキーマ設計と変換が必要 |
| OSM PBF 等のソース配布 + インポート | 元の道路・鉄道属性を取り込む入口として利用できる | そのまま毎回の近傍検索に使う前提にせず、抽出・グラフ化・索引・更新方式を別途評価 |
| GeoJSON、FlatGeobuf 等の地物ファイル + メモリ上のグラフ/索引 | 小地域の検証や地物データ交換を簡素化できる。形式によっては空間索引を利用可能 | 大容量時の起動時間・メモリ、属性結合、差分更新、参照整合性の管理負担を比較 |
| PostGIS 等のサーバー型空間DB | 集中管理や広域の空間問い合わせに適する可能性 | 常設サービスの運用・接続依存が増える。中央Webサービスを必須にしない既存方針との整合が必要で、通常クライアントの必須構成とは決めない |

MBTiles（SQLite を使うタイル格納）や PMTiles 等のタイルアーカイブは、背景配布・取得の候補として別に比較する。タイルの保存形式がリレーショナルDBかどうかと、接続・属性を問い合わせ可能な地理DBを持つことは同義ではない。

### 空間検索・更新・配布・オフライン

- 代表的な操作は表示範囲の抽出、カーソル近傍の道路/鉄道候補、線への投影、接続をたどる追従候補。空間索引と接続グラフの双方が必要かを検証する。
- 地域別抽出、地域境界をまたぐ接続、取得時点・版・ハッシュの管理、再インポート／差分更新、更新中の参照整合性とロールバックを比較する。
- 地図パッケージとワールド保存を別管理し、保存には必要なデータ版や参照情報を持たせる案を検討する。元データが消えた時の建設済み線形はゲーム側の確定形状から復元できる設計を優先して検討する。
- オフライン用に何を同梱・ダウンロードするか、地域パッケージの容量、更新頻度、キャッシュ削除、初回取得手順は未決定。公開タイルの無制限取得を前提にしない。
- OSM データのライセンス・帰属・派生データ配布要件と、個別タイル提供サービスの利用条件を分けて確認する。取得できることだけで再配布可能とは判断しない。

### マルチプレイとの関係

- SQLite ファイルを複数クライアントが直接共有更新することをマルチ同期の仕組みにはしない。既存方針どおり、ゲーム状態の更新は権威側で検証・適用する。
- 参照データの版が違う場合に同じ操作で異なる追従結果にならないよう、権威側での形状確定やデータ版固定・不一致検出を比較する。
- 背景表示とゲーム設備の同期を分離する。全員に同じ背景タイルキャッシュを配ることがゲーム同期の必須条件とは限らない。
- シングル、ゲーム内ホスト、headless server で利用できる共通の参照・検証境界を検討する。ネット不通・途中参加・地図パッケージ欠落時の挙動も未決定。

### 判断前の検証

小地域と広域の同一入力で、インポート時間・容量・近傍検索の待ち時間・接続探索・メモリ・更新失敗時の復旧を比較する。高架や地下、分岐、地域境界を含む形状と属性を確認する。3 OS、オフライン、マルチでの版不一致を試し、利用条件と配布方法を整理してから方式を決める。JSON の現行ワールド形式を変更する場合は、参照地理データの方式選定とは別に保存互換性を検証する。
## OpenStreetMap normal background (2026-11-13)

OpenStreetMap Standard is now the initial online background. GSI remains selectable; the explicitly fictional offline sample remains available without a network connection. Tile failures never block world editing, building, or local save/load. Offline real-world maps are not implemented: distribution, licensing, attribution and a suitable offline-capable provider require a separate design. Standard OSM tiles must not be downloaded for offline use.

`mapProviders.ts` isolates provider URLs/attribution from the camera and world geometry. OSM displays `© OpenStreetMap contributors` linked to https://www.openstreetmap.org/copyright. The renderer only requests tiles intersecting the current cropped viewport, at most 20 at once, after a 250ms camera debounce. There is no prefetch, bulk-download, automatic retry or application-managed cache. WebView/browser HTTP caching remains unchanged; no cache-busting query or no-cache header is used. Provider switching remounts the tile layer to avoid mixing successful/failed state across equal z/x/y IDs.

Tauri's documented window `userAgent` is set to `Rosenfu/0.1.0-alpha.1 (+https://github.com/mei8n/rosenfu)`. The CSP permits images from only the existing GSI host plus `https://tile.openstreetmap.org`; no wider network permission was added. Browser previews retain the browser's normal UA and Referer behavior. Configuration and unit tests are verified, but the actual native outbound UA/cache behavior and live map rendering still need an interactive check. No live-tile bulk tests were run.

Policy: https://operations.osmfoundation.org/policies/tiles/ . OSM Standard is a best-effort community service, not a guaranteed backend or an offline asset source. Reassess provider/hosting before broad distribution. Displaying the map does not enable snapping to real roads or railways.

## シングルプレイのオフライン要件（2026-11-12）

**採用方針:** シングルプレイはオフライン動作可能にする。ネット接続がないことだけを理由にゲームや既存ワールドを使えなくする設計を避ける。これは要求であり、現在のオンライン背景表示がそのままオフライン実地図に対応済みという意味ではない。

- ゲーム状態・建設済みの設備・保存再開は、オンラインのタイル配信や地理情報検索APIの成功を必須にしない。
- オンラインOSM等の背景表示とは別に、オフライン実地図の適法な事前入手・保存方法を設計する。取得可能範囲、地域選択、データ量、配布形態、更新、版管理、帰属表示、ライセンス条件を比較する。
- 公開タイルサービスの通常表示許可から一括取得・オフライン利用・再配布の許可を推定しない。条件に適合した地図パッケージやデータ配布経路を選ぶ。
- オフライン背景は見た目の実地図、OSM道路・鉄道ガイドは追従候補の形状・属性・接続情報。どちらか一方が存在すればもう一方も使えるとはみなさず、参照地理DBの保存方式と合わせて整理する。
- 未取得地域や不足データの表示と取得案内、地名候補や追従機能が利用できない場合の挙動は未決定。地図が不足しても、既存ワールドを壊す・空に置き換える・使用不能にすることを回避する。
- 必要な地理参照情報のワールド側保持と別パッケージ依存の境界を決め、背景の入替や更新でプレイヤー設備を変化させない。
- 全国データを常に全量同梱するとは決めない。基本インストール・追加地域パッケージ・ユーザーによる取込等を比較し、容量と配布権を検証する。

**現段階:** オフライン実地図パッケージの取得・管理・更新、OSMガイドのオフライン運用は未実装。サンプル背景が表示できることと、シングル全機能のオフライン受入試験が完了したことは区別する。通信を切った起動・既存保存の再開・編集・保存・再読込と、地理パッケージ欠落や破損時の動作を将来検証する。
## 実在駅の参考表示（追加要望、未実装）

参考ゲームで実在路線の駅が地図に出ないと不便だったとのユーザー説明を踏まえ、Rosenfu では OSM 等の実在駅を地図上の参考情報として表示する。ゲーム内に駅設備を自動生成する要望ではない。

- 実在駅のマーカー・名称と、プレイヤーが建設するゲーム内駅を視覚的に区別する。色だけに依存せず、形状・ラベルや凡例も検討する。
- 参考表示の ON/OFF、ズームに応じた表示量・名称省略、ゲーム内駅と重なった時の表示・選択方法を検討する。具体的な既定値や操作は未決定。
- 表示タイルに駅名が含まれるかとは別に、OSM の駅地物を参照レイヤーとして保持・描画する方式を候補にする。駅・停留所・ホーム・出入口などの分類、同じ駅を表す複数地物の統合は検討が必要。
- 実在駅レイヤーの元ID、出典、取得時点・版を管理し、参照地理データの更新・帰属・配布条件と整合させる。マーカーを表示するだけで正確な位置・現存・営業状況を保証しない。
- オフライン実地図パッケージに駅地物も含めるか、別パッケージにするかは未決定。事前に適法に保存した範囲では通信なしで参照できる方式を検討する。
- 実在駅データが未取得・不完全でも既存ゲーム駅とワールドの利用を妨げない。不足状態を明示し、参考駅がないことを現実に駅が存在しない証拠としない。

現在は追加要望として記録した段階であり、OSM 実在駅の抽出・統合・個別参考レイヤー・ON/OFF・オフライン表示は未実装。オンライン背景画像に偶然含まれる駅表示を、この機能の実装完了とは扱わない。
## 2026-11-13: 表示解像度の補正

固定1000×600の論理座標のタイルを大きなウィンドウに引き伸ばしていたため、
Full HD等では256px画像が約2倍に拡大されていた。画面サイズとdevicePixelRatioから
最大2段上のタイルズームを選び、同じ地理範囲へ小さく配置するよう変更。
カメラ・駅・線路の座標や編集ズームは変えない。OSMは既定、地理院・オフライン自作背景は選択式。

表示範囲に交差する画像だけを最大128枚まで取得し、超過時は詳細度を1段下げて全面を維持する。
画像配信上限はOSM ZL19・地理院淡色ZL17。先読み・バルク取得・永続キャッシュは追加しない。
高DPIや巨大画面で常に1デバイスピクセル相当になる保証はない。上位ズームの画像なので
地名の密度・文字の見かけの大きさは以前と異なる。高解像度ベクターマップ化ではない。

地理位置と全面被覆、取得上限、画面/DPI変更、オフライン時画像要求なしを自動テスト。
この修正について実ネットワークの画像品質比較・Windows/WebView実機確認は未実施。
