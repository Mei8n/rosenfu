# 運行系統の基本構造

## この段階の目的

設備・路線と独立した運行系統を、コアと保存形式に追加します。列車はまだ運行しません。
列車種別・時刻・運行本数・車両・容量・運賃は未確定のままにし、このモデルに仮の必須値を持ち込みません。

## データ

OperatingService は次の項目を持ちます。

- id: 独立した ServiceId。既存と同じ採番器による十進数文字列。
- owner: 運営会社の CompanyId。
- name: 系統名。
- start: 経路の起点駅。
- tracks: 起点から順番に通れる線路 ID の列。設備を複製せず参照する。
- stops: 経路上の駅出現位置を表す整数列。0 は起点、線路数と同じ位置が終点。

たとえば A → B → C → A では駅出現位置は 0、1、2、3 です。
stops=[0,2,3] は B を通過し、最初と最後の A を別々の停車として扱います。
駅 ID の集合では同じ駅の再訪を区別できないため、出現位置で表現します。
現在は起終点への停車を必須とし、中間停車は任意です。
stops は厳密昇順・重複なし・経路内でなければなりません。

路線 ID は参照しません。現在の路線も順序付き設備列を持ちますが、
路線の名称・起点・経路を変更しても系統の運行経路を暗黙に書き換えません。
同じ設備を複数の系統が参照でき、設備削除・変更は参照整合性の検証対象です。
将来の経由路線表示や路線との関連付けは別途設計します。

## 検証と責務

存在する会社・起点駅・線路、連続した非空の経路、停車位置を検証します。
失敗時はワールドと採番状態を変更しません。編集は既存 ID を維持する replace を使います。
所有会社の参照確認は行いますが、利用者の操作権限や他社線使用契約を認可する機能ではありません。
この制御は将来の権威サーバーと会社間契約の設計が必要です。

## 保存と移行

保存スキーマ2で services を必須にします。スキーマ1の正式な旧構造は、
既存エンティティ・ID・採番器を維持したまま、空の services を追加してメモリ内で読み込みます。
路線から系統を勝手に生成しません。読込だけでファイルを書き換えません。

明示保存時にスキーマ2へ更新し、スキーマ1の元バイト列を直前バックアップに残します。
未知のフィールドや未対応版は黙って削除せず拒否します。
古いアプリでスキーマ2を開くことは保証せず、旧アプリは非対応版として拒否します。
これは最初のアルファ移行であり、ベータの互換性条件をすべて満たしたものではありません。

## 操作・未実装

コア API の add_service と検証済み replace で作成・変更でき、CLI inspect で件数を確認します。
画面の「系統」タブから作成・編集できます。
系統を含むワールドを既存画面で読み込み、路線・会社を編集して保存しても系統は保持します。

列車生成、時間帯・曜日ダイヤ、種別、待避・折返し・線路容量、旅客経路探索は未実装です。
停車列だけで物理的な運行可能性を保証しません。

## 系統編集画面

系統名と起点駅を指定し、接続する線路を順番に追加します。経路上の駅を出現順に表示し、中間駅の停車・通過を切り替えます。起終点は停車固定です。同じ駅を再訪した場合も各出現位置を別々に設定できます。

新規・既存系統の切替やワールド読込では、未適用の編集を破棄する前に確認します。未適用の編集がある間はワールド保存を無効にし、適用後に保存してください。適用に失敗した場合は編集内容を保持します。経路変更で停車設定を初期化する場合は画面に明示します。

確認手順: A→B→A の経路を作り、中央のBを通過にする。適用して保存し、再読込後に系統ID・経路・停車位置が一致することを確認する。別系統切替・読込の破棄確認をキャンセルして編集中の内容が残ることも確認する。試験には専用ワールドを使う。

検証: Rustワークスペース64件、フロント43件のテストを実施。分離Edge＋模擬エンジンでもA→B→Aの中間停車を解除し、同じ系統IDで適用・保存・再読込後に停車位置[0,2]が残ることを確認。模擬ブラウザ検証はネイティブWebViewの実操作確認ではありません。

## 路線と系統の作成フローに関する追加方針（2026-11-12）

上記は現在の手動経路編集の説明であり、以下のフローは追加要望・未実装。

1. 路線タブで起点・終点を選ぶと、中間駅を路線へ自動追加する。必要な駅は路線の駅一覧から除外できる。これは物理駅の削除や通過指定ではない。
2. 系統側で、その路線上の出発・経由・終点を指定する。路線名と系統名は同じでも別でもよく、上野東京ラインのような運行系統名を扱えるようにする。
3. 各系統は各駅停車を基本に、列車種別・停車駅を設定する。

路線と系統の分離は維持する。先行参考案の「路線の中間駅を通過扱いにしてから一括で停車に変更」は撤回する。
現在の `OperatingService` は路線IDを参照しないため、関連付け、路線の駅一覧、種別との関係を追加設計する必要がある。経路分岐・複数候補・同駅への再訪などの規則は未決定。
詳細と他の追加要望は[追加設計メモ](construction-and-service-planning.md)を参照。
## 路線からの系統下書きプレビュー（2026-11-13）

`preview_service_from_route({ routeId, fromOccurrence, toOccurrence })` は路線上の指定区間を読み取り専用で解決する。位置は物理経路上の駅出現位置（0起点）であり、所属駅一覧の添字ではない。同駅再訪は別の位置として明示指定し、逆方向にも対応する。路線の物理駅順は `World::route_path_stations` で取得できる。

返値は `route_id`, `start`, `tracks`, `stations`, `requires_stop_selection: true`。各 station は `station_id`, 下書き内の `occurrence`, 元路線内の `route_occurrence`, `route_member` を持つ。**停車列は返さない。** 所属外駅だから通過、所属駅だから停車とは決めず、利用側が停車設定を明示確認して既存 `save_service` へ渡す。既存APIが求める起終点停車は維持する。

選択区間がTrackのみの場合に対応し、区間内にAlignmentがあれば明確な未対応エラーを返す。路線全体が混在していてもTrackのみの部分区間は取得できる。設備や系統の生成、ID採番、路線と系統の永続関連付けは行わず、保存schema 4も変更しない。ユーザーが明示適用するまでは既存系統や下書きを上書きしない。古いpreviewはワールド変更時に破棄し、再取得すること。

このAPIはバックエンドの作成補助であり、路線編集への系統自動追従やAlignment上の運行対応ではない。UIの接続は下記の範囲で実装済み。ネイティブ動作確認は別途必要。


### 系統パネルの区間取込UI

- 「路線区間から新規系統下書き」で元路線と駅の出現位置を選び、区間を確認する。表示番号は1起点、API値は0起点。同じ駅の再訪は別番号、逆方向も選べる。
- 現UIは路線全体がTrackのみ（旧Routeと全TrackのRoutePath）に限定する。Alignment混在路線は部分区間もUIでは未対応表示。バックエンドAPIの対応範囲より狭い。
- 各駅の路線所属/所属外を表示する。「全駅停車（路線所属外も含む）」を最初の選択肢として提示するが、自動選択はしない。「個別指定」も初期表示は全駅停車で、起終点は停車固定。
- 所属外駅を含む停車/通過を確認するチェックが必要。停車設定を変更すると確認を解除する。路線所属外を自動的に通過扱いにはしない。
- 既存系統が選択中、または未適用の系統下書きがある場合は取り込めない。先に適用/破棄して「新規系統」へ切り替える。取込は新規下書きに限定し、独立した系統名は空欄から入力する。
- 取込時には `save_service` を呼ばない。系統名・停車設定を確認して「系統を適用」で初めてWorldへ反映し、上部の「保存」でファイルへ保存する。既存系統は上書きしない。API失敗時は下書きを残す。
- 路線/端点/Worldを変えたら古いプレビューを無効化する。任意の複数経由点・列車種別・Alignment運行・路線編集への自動追従はまだ未対応。

## 建設線形対応の新形式系統（schema 5）
「路線全区間から新形式系統」で既存路線の全物理区間を独立コピーできる。建設線形（Alignment）と駅間接続（Track）の混在に対応し、単一路線の全体コピーのみで、部分区間指定・途中経由の追加指定・複数路線の結合はこの新UIでは未対応。従来のTrackのみ区間取込と手動編集も残す。

停車方針は自動確定しない。全駅停車または個別指定を選び、所属外駅も含めて確認し、独立した系統名を付けて適用する。端点は停車固定。新形式の停車位置は区間キー＋駅ID（始点は専用参照）で保存し、中間駅が増えても既存停車駅をずらさない。途中に新設された駅は自動停車にならない。

保存済み新形式系統は経路と停車/通過の参照表示のみで、既存系統の変更は未対応。旧フォームで空tracks/stopsとして上書きしない。経路が参照する駅は非停車駅も削除・駅設置Undoを拒否し、参照Trackも削除不可。別下書きや既存系統を上書きせず、新規作成に限定する。失敗時の名前と停車指定を保持する。Worldが変わると古いプレビューと停車確認を破棄して再確認を求めるが入力名は残す。明示的なWorld読込成功で下書きを解除する。Windows実機操作・実行ビルドは今回未確認。
