## 1. 現在地

最新の要件別状態と未達・未統合・GUI未確認は[0.1受入](alpha-0.1.md)を正とする。古いPR #66時点の一覧を現在の完成判定に使わない。

照合対象には区間線路数、7段階高さと縦断・アンカー別高さ、分岐構造、範囲選択、参照保護、複数スロット、路線/系統編集、複数路線直通binding、系統色/形/記号、実在線路の取得/追従、OFM必要範囲の道路追従を含む。書出形式はschema25で、旧1〜24は非破壊で拒否する。OFM必要範囲取得・道路追従・踏切派生判定と、境界を跨ぐ経路の根拠保存/延伸/接続/高さ対応は統合済み。取得失敗・coverage不足は未確認として扱い、全国のデータ完全性は保証しない。全国45地域の水域取得、線路・地上駅中心の水域判定は統合済みだが、全国全地点の精度や実機受入の保証とは別。部分高さ変更の再設計は統合済みだが、実機受入は別途必要。列車が走り旅客を運ぶゲームとしてはまだ未完成。

本人指定のゲーム値は1段6m、通常45‰・高速30‰・トラム45‰。勾配は建設可否に用い、列車速度補正には使わない。水域上への地上敷設禁止は陸水判定を用いる。正常な非提供時の粗データ利用と、必須データの通信失敗・破損・未取得による保留を区別する。費用計算・課金は将来。

## 2. 直近の順序（作業案、日程・機能追加の確約ではない）

1. **建設・保存の実機受入**: 直線/円弧、両端延伸、既存/計画駅、複数経路・個別着工、手動/自動保存、再読込。既存セーブとは別のテストワールドで実施し、旧版へ戻す場合は旧セーブのコピーを用いる。
2. **0.1の編集経路を閉じる**: PR #66で統合した新方式の系統名/停車編集、部分区間取込、経路再設定を保存往復まで確認する。停車編集は経路・leg key・IDを保持する。経路再設定は旧停車を自動移植せず、元ServicePathとの一致を確認して新しいleg keyを割り当て原子的に適用する。旧Track編集を実装し直さない。
3. **0.2の道路交通**: [道路交通計画](road-transport-plan.md)に従い、共通道路データを再利用してバスとトラムの道路上設置を実装する。道路追従だけの現行機能を併用軌道やバス運行の完成と扱わない。
4. **運行の最小縦切り**: 共通時計・簡易ダイヤ・車両性能・駅間走行をRust共通処理に置く。短駅間の最高速度未到達を試験し、その運転時分を旅客側も使う。
5. **固定小地域ODから流動へ**: [需要・流動計画](demand-flow-plan.md)の段階A/B。外部データ未取得でも合成fixtureで保存則・経路配分・性能を検証する。
6. **目的/時間帯・運賃/収支・規模拡大**: 同計画の段階C/D。人口変動やマルチ通信の本実装を同時に詰め込まない。

本人の追加指定により、線路数・高さ・分岐・道路踏切は0.1で今実装する。水域・道路/踏切の既知制限と実機未確認を先に解消し、運行機能へ進む前に基本構造の受入を通す。

## 4. 実装時の共通完了条件

- 対象・非対象・失敗時の挙動を先に明記し、既存の保存/参照/所有権を保護する。
- 自動試験・静的検査・該当CIと、必要なGUI受入を分けて記録。未実施を成功扱いしない。
- 変更はクラウドで作業し、作業開始時にブランチをリモート作成、区切りごとにcommit/pushして反映確認する。
- PC反映は本人がGitHub Desktopで開発統合ブランチを手動更新する。自動checkout・反映をしない。
- mainへのmergeはユーザーが確認した対象・範囲に限る。未統合・他人作業・未保存のブランチを整理名目で消さない。
- 作業完了時に本書の状態と詳細仕様を更新。設計だけなら実装ありへ進めない。
