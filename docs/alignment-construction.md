# 路線先行建設とホーム形状（試作）

駅を置く前に、名前付きの地理座標列 `Alignment` を建設する。駅は線形上の距離割合に結び付け、ホーム長・幅を実メートルで保存する。UI は曲線を座標列にサンプリングし、同じ保存線形から線路と平面ホームの帯を描く。現行試作は帯形状で描画する。後続要望では縮小時を点、拡大時を帯に切り替える方針へ変更しており、追加設計メモを参照する。

- 線形と駅位置は地図 SDK・タイル提供元から独立した緯度経度。
- ホーム長 20〜1000 m、幅 4〜100 m。線形の全長を超えるホームは拒否する。
- 端点付近はホーム全長が線形内に入るように駅中心を補正する。配置後の長さ変更でも同様。
- 既存の駅・駅間接続・経路 (`Route`)・運行系統は保持する。新駅も同じ駅一覧から経路編集に利用できる。
- `Alignment` は物理的な建設線形、既存 `Route` は駅間接続をたどる順序付き経路。現段階では建設線形から駅間接続・系統を自動生成しない。
- 保存スキーマは 6。旧1〜5を段階移行し、既存経路・系統を保持、旧版には空の出典sidecarを補う。既存ID・設備を保持し、明示保存まで元ファイルは変更しない。旧アプリはschema6未対応。詳細は[保存仕様](storage.md)と[出典仕様](alignment-provenance.md)を参照。

## 今後の範囲

ホーム有効長から、車両長・編成両数に応じた収容可否を計算する。今回保存する `length_m` はその基準になるが、車両・編成・列車長・収容力・はみ出し停車の判定は未実装。

OSM 等の実在線路・道路へのスナップ／トレースは未実装。背景タイルだけではなく参照用ベクトル形状が必要になる。将来取得した参照形状を建設線形の入力へ変換し、提供元データとゲーム内線形を別管理する方針。今回地図提供元は変更しない。

距離は球面上の局所近似。詳細な土木線形（緩和曲線・勾配・曲率制限）、ホーム同士の干渉、線路分岐、経路自動分割は別工程。

追加の建設・駅長・高さ・敷設補助・費用の方針は[追加設計メモ](construction-and-service-planning.md)を参照。試作の制限と最終的な製品仕様は区別する。
