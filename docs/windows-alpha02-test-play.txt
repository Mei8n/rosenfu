Rosenfu α0.2 / Windows x64 内部テスト

1. 起動
配布担当から受け取ったQA ZIPを展開して、中の -setup.exe を起動する
Git・GitHubアカウント・Visual Studio Codeは不要
WebView2が未導入の場合、セットアップ中にネット接続が必要
この版は署名なし。配布元が確認できない・Windowsの管理ポリシーで
止まる場合は実行せず、配布担当に連絡する

インストール後、スタートメニューの「Rosenfu Alpha 0.2 Test」から起動
地図・道路・水域などのオンラインデータ利用には別途ネット接続が必要
通常版とは保存先が別。通常版のセーブは自動で取り込まない
検証はテスト新規ワールド、またはバックアップを取ったコピーで行う

2. 最初に試すこと
(1) 新規ワールド作成 → 地図表示 → 線路と駅を作る → 保存 → 終了 → 再開
(2) 通常版がある場合は、両方が別に起動して各保存一覧が混ざらないことを確認
(3) ネット切断・復帰時に、未取得データの表示や再取得の挙動を確認
(4) テスト版のみを更新しても、両方の保存一覧が混ざらず各ワールドを開けることを確認
(5) 路線・系統の編集中は、現在の始点または終点を選んでから地図で新しい駅を指定
    中間駅を選んだだけでは端点が変わらず、取り消すと元の状態に戻ることを確認
(6) 系統のダイヤ設定で始発、終発、間隔を指定し、時刻を進める
    走行・停車・待機が表示され、停止中に時間が進まないことを確認
(7) 都市タブで起終点と仮の需要を指定。新線や増発で結果が変わり、
    鉄道・バス利用、代替、未達、探索未解決が区別されることを確認
    実人口の予測ではなく、鉄道とバスの乗り継ぎは未対応
(8) 建設の道路交通タブで架空の検証道路を明示的に有効化
    地図で起終点を選び、バス停・バス系統・ダイヤを設定し、
    トラム軌道の着工・関連解除・撤去を確認する
    架空の検証道路は実在道路の通行規制を再現しない
(9) セーブ名を変更して終了・再起動し、同じワールドと運行設定が開けることを確認

3. 不具合の伝え方
BUILD.txtのcommit、Windowsのバージョン、発生時刻、テスト項目番号、
操作手順（直前の操作から）、期待した結果、実際の結果、再現回数を添える
地図上の問題は場所とズームの目安も書く
スクリーンショットや動画は個人情報を除いて添える
例: 3回中3回 / ワールド作成 → 建設 → 2地点をクリック → 保存で停止

4. パッケージ照合
公開リポジトリのActionsではインストーラーもZIPもアップロードしない
配布担当は別途承認済みの非公開経路から受け取ったZIPのSHA256を確認する
中のZIPは展開するとPACKAGE-SHA256SUMS.txtで各ファイルを照合できる
PowerShellで Get-FileHash -Algorithm SHA256 をインストーラーに実行し、
SHA256SUMS.txtと照合する。不一致なら起動せず、再取得する

BUILD.txt の kind=preview はパッケージ工程の確認用。テストプレイには転送しない

5. 同梱データ
data-and-notices に、東京中心部道路データと日本周辺の概略水域モデルを
機械で読める元の形式・出典・利用条件付きで同梱する
道路と水域のOpenStreetMap由来データはアプリ本体とは別にODbL 1.0
（© OpenStreetMap contributors、https://www.openstreetmap.org/copyright）
https://opendatacommons.org/licenses/odbl/1-0/
水域モデルの湖沼データ: Made with Natural Earth
LINE Seed JPの条件はLINE-Seed-JP-OFL.txtを参照
アプリの第三者ソフト通知・MPL対象ソース案内はdata-and-notices/softwareを参照
オンライン配信元のデータや個人のワールドデータはこのフォルダには含まれない


6. CIと配布の区別（配布担当向け）
Windows CIはステージ済みインストーラーのハッシュを照合し、実際の導入・起動・
合成ワールドの保存と再起動後の再読込・通常版プロファイル非干渉・
通常アンインストールでのセーブ保持を確認する
開発環境なしのクリーンWindows、WebView2が未導入の初回インストール、
通常版が既にある場合の共存、オンラインデータの実取得は別途確認が必要
ソフト通知の自動生成はアプリ依存が対象。NSISスタブ/プラグイン・
WebView2ネイティブ部材の条件とオンラインデータ提供条件は別途確認する
BUILD.txtでnative-installer-notices-review=pendingの場合はCI成果物を外部に転送しない

dev/alpha-0.2-integration の push が起点
Checkの3OS成功後、Windowsパッケージ工程まで成功した同一SHAの検証ログを確認する
公開CIのログは検証結果だけ。配布する場合は、別途承認済みの非公開ビルド・受渡しが必要
Actions runの存在しない過去SHAは、別のSHAの成果物で代用しない
過去SHAを再現する場合、隔離したWindows実行環境で対象コミットを完全SHAで固定し、
検証スクリプトの版とビルド元コミットを別々に記録する。通常の統合成果物とは区別する

7. ネイティブ通知と統合コミットの検証
Windows QAの圧縮はzlibを使用する。CIはNSISの実ペイロードを一覧化して
未知の実行ファイル・DLL・圧縮方式を拒否し、NSIS/Tauriと同梱DLLの通知、
Microsoft WebView2 SDK 1.0.3800.47の公式ライセンスを
data-and-notices/native に記録する。SDKのx64静的ローダーとCargo入力の
SHA256が一致する場合にだけ通す。WebView2本体は引き続き同梱しない
NSIS Tauri DLLの配布ビルドに使われた完全な依存版は別途確認し、
ライセンスの最終レビューが済むまでpendingの成果物を配布しない

通常の統合pushでは、Checkの実行に使ったワークフローSHAとビルドした
ソースSHAの完全一致を確認し、3OS checksの結果をBUILD.txtへ記録する
Windowsスモークを通過したインストーラーのSHA256をZIP直前に
再照合し、同梱のネイティブ情報も同じインストーラーを指すことを確認する
統合pushのCheckがないときは、この記録のない成果物を統合版と呼ばない
