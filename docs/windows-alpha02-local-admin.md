# Windows x64 ローカル QA セットアップ（管理者用）

通常版と公開ソース側の既存 QA プロファイルは変更しません。ローカル
管理者用だけ、既存 QA 設定の **後に** 専用設定を重ねます。下記の実行は
管理者用インストーラーの生成であり、インストールはしません。専用設定の
`silent: null` は、元の設定にある WebView2 自動導入用の項目をマージ時に
消すための指定です。

```powershell
npm run tauri -- build --ci --target x86_64-pc-windows-msvc --config src-tauri/tauri.alpha02-qa.conf.json --config src-tauri/tauri.alpha02-local-admin.conf.json -- --locked
```

- セットアップには管理者権限が必要です。配置先は
  `%ProgramFiles%\rosenfu`（64ビット側）に固定します。別の場所や
  `/D` での上書き指定は使えません。すでに存在する未登録フォルダーは
  空でも引き継がず、他のインストールを移動・削除しません。
- この方式でインストールしたコピーは、同じフォルダーのまま新しい
  セットアップで上書き更新します。古い版、不整合や別の場所を示す登録は
  拒否します。他のインストールのアンインストーラーは実行しません。
- 以前の「ユーザー用」QA 版を入れている場合は、一度だけ元の Windows
  ユーザーで Windows の設定から旧版を手動アンインストールしてください。
  **アプリのデータを削除する項目は選ばず**、不安なら先にセーブをバックアップ
  します。昇格に別の管理者資格情報を使用する場合、セットアップが元のユーザーの
  旧登録を検出できるとは限りません。ローカル管理者用の新しいアンインストーラー
  は正しいフォルダー、登録済みの製品とバージョンを確かめてから削除し、
  ユーザーごとのセーブには触れません。別の場所への指定やリンク先は拒否します。
- [Microsoft Edge WebView2 Evergreen Runtime](https://developer.microsoft.com/microsoft-edge/webview2/#download-section)
  のシステム全体へのインストールが必要です。通常の Windows に既に入っていれば
  追加作業は不要です。未登録・ユーザー単位のみ・更新が必要なときは、
  Microsoft 公式の x64 ランタイムを管理者として導入してから再実行してください。
  このセットアップは Windows のマシン登録を読むだけで、ランタイムをダウンロード
  したり、更新プログラムを実行したりしません。
- セーブ先は同じ Windows ユーザーの
  `%APPDATA%\io.github.mei8n.rosenfu.alpha02qa\prototype\saves` のままです。
  通常版の保存先とは別です。インストール後のアプリは通常のユーザーとして起動
  します。既存の公開 QA セットアップの上からは導入しないでください。

## 旧 QA の登録だけが残っている場合

Windows の「インストールされているアプリ」から旧 QA を削除した際に、旧
アンインストーラーが見つからない場合だけの手順です。旧版のインストール先を
確認できない、外付けドライブが接続されていない、旧版がまだ使える、または判断
できない場合は、登録を削除せず先にその状態を確認してください。

1. **旧版を入れた Windows ユーザー**で操作します。次のセーブフォルダーを
   別の場所にコピーし、コピーが読めることを確認します。
   `%APPDATA%\io.github.mei8n.rosenfu.alpha02qa\prototype\saves`
2. レジストリ エディターで、次の **HKCU の一つのキー**だけを確認します。
   `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Uninstall\Rosenfu Alpha 0.2 Test`
   `DisplayName` が `Rosenfu Alpha 0.2 Test` で、`UninstallString` が
   既に失われている旧 QA のインストール先を指すことを確認します。値は
   確認用に読むだけで、コマンドをコピーして実行したり書き換えたりしません。
3. 対象キーを右クリックして「エクスポート」し、選択した部分だけを `.reg`
   ファイルにバックアップします。保存後、先頭のキー名が手順 2 と同じことを
   テキストとして確認します。**両方のバックアップを確認してから**、対象の
   HKCU キー一つだけを手動で削除します。親の `Uninstall`、HKLM、ほかの
   QA/通常版の登録、フォルダー、セーブには触れません。キーが見つからない場合は
   別の名前や別のユーザーで代用しません。
4. 管理者用セットアップをもう一度実行し、通常ユーザーで起動して旧セーブが
   開けることを確認します。バックアップした `.reg` は登録を戻す場合だけに
   保管します。取り込んでも旧アンインストーラー自体は戻りません。

この操作で消えるのは Windows の旧版一覧への登録だけです。セットアップは
登録を自動削除せず、旧アンインストーラーも起動しません。

## QAの境界

既存の `Smoke-WindowsAlpha02.ps1` は従来の HKCU 版を確認する専用スモーク
です。管理者用を渡してそのまま動かすものではありません。管理者用を検証する
場合は使い捨ての Windows x64 VM で、通常版と既存ユーザープロファイルを持ち込まず
次を順に確認します。

0. 依存ソフト：WebView2 のマシン登録がない状態（ユーザー単位のみも含む）では、
   製品ファイルや登録を作らず終了する。Microsoft 公式の x64 ランタイムを
   マシン全体に導入後、同じセットアップで先に進める。
1. 初回：通常のユーザーから起動 → 管理者昇格 →
   `$PROGRAMFILES64\rosenfu` に配置 → HKLM 64-bit 登録。完了後アプリが通常の
   ユーザーとして起動し、そのユーザーで保存・再起動できる。
2. 更新：異なる新しいバージョンのセットアップを起動すると、配置先を
   変えずに更新し、セーブが再開できる。
   実行中のアプリでファイルが書けない場合や、古いセットアップ・違う場所の
   指定は拒否される。実行ファイルやアンインストーラーの書き込み失敗では
   新しい版の登録を行わない。ただし書き込み済みのファイルまで自動で戻す
   処理ではないため、途中で失敗したときはフォルダーや登録を手動で確認する。
3. 拒否と移行：既定フォルダーに別製品のファイル、またはリンクがある場合は
   書き込まない。旧 HKCU 版からの手動アンインストール後、同じユーザーで
   セーブを確認。新しいアンインストーラーが実行ファイルと自身の登録のみを消し、
   確認用セーブや通常版のファイル・登録を残す。アンインストーラーに別の
   `_?=` を指定する、登録・版番号を崩す、リンク先へ置き換えると、削除を行わない。

Tauri CLI 2.12.4 の公式 `installer.nsi`（`tauri-cli-v2.12.4`,
`993038c49185307dfc895ab7657d77ca0d5ed7c7`、元 Git blob
`75efe3da953fb6914a08359705d94d9ee8732542`）を MIT 条件で
`src-tauri/nsis/` に改変同梱しています。QA の表示名、識別子、製品の版番号、
配布方式は元の QA 設定から継承します。Tauri のピン更新時は元テンプレートとの差分と
上記 VM 検証を見直してください。

この管理者用セットアップを第三者へ渡す場合は `LICENSE-Tauri-MIT` も同梱します。

実行ファイルの上書きとアンインストーラー書き込みは Tauri 2.12.4 が使用する
[NSIS 3.13 の実装](https://github.com/NSIS-Dev/nsis/blob/v313/Source/exehead/exec.c)
に従い、必須ファイルのスキップを禁止し、検出された失敗を版登録前に中止します。
停電等を含むファイル一式のトランザクションやロールバックは保証しません。
