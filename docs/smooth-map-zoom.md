# 滑らかなズーム

2026-11-13 暫定実装。整数ZLを即座に±1していたホイール操作を、小数ズームへ変更。

- wheelのpixel/line/page単位を換算し累積する。1イベントの最大移動は0.75 ZL、通常100px相当は0.25 ZL。
- 160msのrequestAnimationFrame補間で表示。途中で反転・追加入力できる。マウス下の緯度経度を固定する。
- 画面描画とクリック逆変換は同一カメラ。緯度経度・線形・駅データは変更しない。日本付近の表示範囲端では範囲制限を優先。
- ドラッグ開始・地図クリック・ツール/背景切替・直接移動・アンマウントは補間を中止。Ctrl/Meta/Alt/Shift付きwheelは奪わない。
- prefers-reduced-motionでは補間しない。＋/−ボタンとキーボードの + / -（テンキー含む）は画面中心を基点に1 ZLずつ、ホイールと同じ160ms補間で移動する。連打・キーリピートは目標倍率へ累積し、上下限で止まる。入力欄・編集可能領域・IME変換中やCtrl/Meta/Alt併用時はキー操作を奪わない。
- 表示小数ズームとは別に画像要求のZLは整数。停止250ms後に可視範囲を要求する。
- 読込済みの旧画像を最大128枚保持して、新画像のロード中にも同じ位置へ描く。新画像が全部成功/失敗したら旧画像を除去する。失敗は隠さない。背景切替で旧層も除去。
- 先読み、オフライン地図ダウンロード、永続的アプリキャッシュは追加しない。ブラウザHTTPキャッシュは従来どおり。
- 駅ポリゴンはワールド変更時だけ計算、タイル読込件数が同じなら親へ再通知しない。

小数ズーム位置精度、整数タイルURL、カーソル基点、累積・方向反転・上限・取消・後片付け、旧画像保持/失敗、UIからの操作を自動検証する。
この段階ではWindows/WebView実機の滑らかさ・大量線形のフレーム時間は未測定。App全体の再描画と参照線検索は残るため、60fpsを保証しない。通信速度によって新しい範囲の地図が出るまでの待ち時間は残る。

## 編集用の最大拡大（2026-11-13）

編集カメラの上限を ZL16 から **ZL20** に拡張した。同じ画面で従来の最大倍率の16倍まで寄れる。
ホイール・＋/−ボタン・キー操作はいずれも既存の同じ補間と上限判定を使用する。
駅のホーム帯と線路は緯度経度から同じカメラで描くため、地図との位置関係や保存寸法は変わらない。

**表示倍率と背景の情報量は別**。既存の配信上限（OSM ZL19、地理院淡色 ZL17）は変更せず、
それ以上は取得済みの上限タイルを拡大表示する。存在しない ZL20 のOSMタイルを要求しない。
細かく編集できるが、ラスター背景の文字・道路がさらに精細になるわけではなく、最大付近ではぼける。
DPI・ウィンドウの大きさによってもぼけの程度は変わる。帰属表示、可視範囲のみの取得、128枚上限、
先読み・一括取得なしの方針は維持する。ベクター背景への変更はこの修正には含めない。

縮小下限は ZL12 から **ZL4** に拡張。通常の横長画面では日本付近の対応範囲
（東経122〜154度・北緯20〜46度）を見渡せる。起動時と「東京へ戻る」は引き続きZL12。
表示領域が対応範囲より広くなる軸は範囲中央へ寄せ、周辺の海域・国外も背景として表示する。
地図の左右反復はせず、日付変更線を超えないよう世界端でカメラを制限する。
縦長ウィンドウではSVGの均等クロップにより全域が同時には収まらない場合がある。
編集対象の対応地域や保存データの座標制約を広げる変更ではない。
