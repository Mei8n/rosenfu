# OSM参照グラフ第一段階の実装範囲

`src/referenceGraph.ts` は独立したオフライン・小地域用のメモリ実装。入力は合成fixtureで検証しており、実OSMの抽出器、経路探索、敷設スナップ、SQLite、UIへの統合は未実装。[将来設計](osm-reference-graph.md)とは区別する。

## 数値・接続契約

- 元nodeの座標とway内segment indexを保持する。座標の補間・平滑化・自動修復をしない。
- 数値は有限値のみ。オブジェクト入力もJSON化より先に検証し、NaN/Infinityをunknownへ変換しない。
- 中点緯度の局所平面近似で長さ1cm未満の辺を拒否する。極小辺を丸めたり近傍検索から黙って除外したりしない。投影でも長さの有限性と正値を検証する。
- 接続には共有する元OSM node、同じmode、同じlayer/level/bridge/tunnel属性が必要。座標一致や幾何学的交差は接続にしない。
- 高さ属性のnullは地上ではない。同じunknown属性同士は明示共有nodeがあれば接続する。unknownと既知値の不一致は接続しない。これは保守的な暫定判定であり、橋端など本来接続すべき箇所の解決は将来の課題。

## 距離・範囲・性能制約

- 投影と距離・境界判定は問い合わせ緯度の局所平面近似。測地線距離や実際の線路長を保証しない。半径は最大1000m。高緯度・長いsegment・広域の精度評価は未実施であり、厳密な工学用途や全域スナップには使わない。
- 日付変更線を跨ぐ範囲は未対応。範囲外と候補なしを区別し、検索円が境界に接する場合は`boundary`を返す。`inside`でも元データの完全性は保証しない。
- 5MiB、2万node、4万edgeまで。返却は100件まででtotal/truncatedを返す。入力上限超過は拒否する。
- メモリ版の近傍検索は全edgeを走査し、候補をソートするためO(E + K log K)、一時領域O(E)。接続検索も全edge走査。結果件数の上限は走査量や処理時間の保証ではない。
- 非同期Repository契約でも現在の計算は同期的。UIスレッド上の連続マウス移動に直接組み込む段階ではなく、実データの計測、空間索引、worker/SQLite導入が必要。
