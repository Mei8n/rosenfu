# Windows x64 ローカル QA セットアップ（フォルダー選択・ユーザー用）

通常のエクスプローラーから **ユーザー用**セットアップを起動します。管理者として
実行しないでください。PC 全体に入れる場合は、従来の
[管理者用セットアップ](windows-alpha02-local-admin.md)を使ってください。
管理者用は従来どおり Program Files の `rosenfu` に固定します。

- 初回のみ、普段のユーザーが書き込める内蔵・固定ローカルドライブを選べます。
  既に存在する親フォルダーの下に、新しい `rosenfu` を指定します
  （例：`D:\Games\rosenfu`）。既存のフォルダーを上書きしたり、ネットワーク先や
  ジャンクションを選んだりはできません。`/D` による指定は非対応です。
- 更新時は確認できた同じユーザー用 QA 版を元の場所のまま更新します。場所を変える
  ときは古いユーザー用をアンインストールしてから入れ直します。異なる方式の古い
  QA 登録、PC 共通版、不整合のある登録は自動で移行・削除しません。2 種類の
  セットアップは同時に実行しないでください。他方式の QA 登録を確認した場合、
  ユーザー用アンインストーラーもファイルを書き換えず中止します。
- 同じ Windows ユーザーならセーブは
  `%APPDATA%\io.github.mei8n.rosenfu.alpha02qa\prototype\saves` のままです。
  ユーザー用アンインストーラーはアプリ本体と自身の登録を外し、セーブや指定
  フォルダーのその他のファイルは削除しません。
- Microsoft Edge WebView2 Evergreen Runtime は先に導入してください。ユーザー用の
  セットアップは現在のユーザーまたはマシンの登録を確認するだけです。

## ローカルで作る場合

通常のお試し用 Windows QA 設定のあとにユーザー用設定を重ねます。既存の公開・
管理者用バンドルと名前が衝突しないよう、別の Cargo 出力先に生成してから、
配布するコピーを `*-user-setup.exe` と区別します。各 EXE を通常の QA
セットアップ、または管理者用として取り違えないでください。

```powershell
$env:CARGO_TARGET_DIR = "$PWD\target-qa-user"
npm run tauri -- build --ci --target x86_64-pc-windows-msvc --config src-tauri/tauri.alpha02-qa.conf.json --config src-tauri/tauri.alpha02-local-user.conf.json -- --locked
```

この方式は `asInvoker` に加えて実際の昇格トークンも確認します。ユーザー用に
昇格は要求せず、継承した昇格トークンや確認できないトークンでは拒否します。
パスの検査は通常ユーザー用の入力ミス防止であり、書き込み可能な任意のフォルダー
を管理者権限で安全に扱う仕組みではありません。更新時は各ファイルを同じ
ボリューム上に新規作成し、所定のファイル名へ移します。別名で参照されている
元ファイルの中身へ直接上書きする処理ではありません。ただし、2 ファイルを
一度に交換する処理ではなく、書き込み失敗からの自動ロールバックはありません。
従来の公開用スモークをこのプロファイルに流用しません。

リリース前は使い捨ての Windows x64 VM で、初回の別ドライブ、同じ場所での更新、
ユーザー用アンインストール後のセーブ継続、昇格しての起動拒否、PC 共通版と既存
フォルダーの保護を確認します。Tauri を更新したときは、カスタム NSIS
テンプレートとの互換性も確認してください。第三者へ配布するときは Tauri の
`LICENSE-Tauri-MIT` を添えてください。
