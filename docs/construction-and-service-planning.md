# 建設・駅サービス・旅客選択の追加設計メモ

更新日: 2026-11-12

ユーザーによる Trainsworld の画面・操作説明と Rosenfu への要望を整理した計画文書。
参考ゲームの説明は独立に検証した製品仕様ではない。「Rosenfu の採用方針」は要件上の決定であり、実装済みや実装版確定を意味しない。

## 1. Rosenfu の採用方針・追加要望

### 建設と敷設補助

- 路線・線路を先に描き、その線形へ駅を配置する。
- 線路種別は独立した「通常」「高速」「トラム」の 3 種。「高速トラム」という一つの種別ではない。
- 高速鉄道は高い目標最高速度に適した、できるだけ緩い曲線を優先して敷設したい。具体的な速度、最小半径、曲率計算やカントの値は未決定。
- トラム選択時には道路に合わせるモードが自動で有効になる。ユーザーが無効にもできる。
- トラムの併用軌道・専用軌道を区間ごとに区別する。道路追従は建設操作の補助、併用・専用は設備の属性として分離する案を検討する。
- 通常・高速・トラムそれぞれで単線・複線・複々線を自動敷設し、ズームイン時には個々の線を描画する。
- 敷設結果はいったん計画とし、建設費・維持費の内訳を示す。「着工」で正式な設備へ移行する。
- 高架・地下などの高さ区分で費用を変える。地上で道路と交差する箇所には踏切を自動設置し、追加費用を表示する。トラムの併用軌道との境界や例外は未決定。
- 駅は計画中・着工済みのどちらの線路にも配置できるようにする。
- 列車シミュレーションでは、平面交差やポイントで別列車の進路が干渉することを扱う。交差の描画と、進路接続・競合判定は同一視しない。

### 駅と建設操作

- 駅はズームアウト時は点、ズームイン時は線路のカーブに沿った帯形状とする。以前の「点マーカーを使用しない」という一律の方向から変更する。
- 駅長は「20m 級車両換算の両数」で増減・表示できるようにする。内部の実寸 `length_m` と両立させる。実車の車両長をすべて 20m とみなす決定ではない。
- 駅長に応じて駅建設費・維持費が変動する。列車長・編成両数に応じたホーム収容判定へつなげる。
- Ctrl+Z / Ctrl+Shift+Z で設置を Undo / Redo できるようにする。
- 敷設中も地図をドラッグして移動できるようにする。
- Escape で選択モードから通常モードへ戻る。下書き・選択解除の細部は今後整理する。
- 駅名は周辺地名から自動候補を作る。ペン操作または名前のダブルクリックで編集する。

### 駅運営・満足度・旅客選択

- 駅ごとに有人・無人・委託などの運営形態を設定し、維持費を調整できるようにする。選択は利用者満足度にも影響する。
- 駅長・場所なども維持費の変動要因にする。有人が必ず高満足度になる等の効果方向・係数は未決定。
- 並行する競合路線の選択では路線・駅の満足度も考慮する。駅運営のサービス品質と費用の選択が競争に影響するようにする。
- 駅の要素、列車速度、自宅や目的地から駅までの近さも、満足度や利用先の選択に影響する。
- 既存方針の所要時間・待ち時間・乗換・運賃の総合評価へ追加する。満足度だけで既存の評価を置き換えるものではない。数式、重み、需要分類ごとの差は未決定。
- 会社の基本運賃と路線別の割増・割引率については[要件](requirements.md)の追加予定を維持する。

### 路線と運行系統を分離した作成フロー（最新方針）

- 線路を建設しただけでは路線や系統を自動作成しない。路線タブから新規の路線を作る。
- 路線作成時に起点・終点を選ぶと、間にある駅を自動で路線へ追加する。必要に応じて対象の駅を路線の駅一覧から除外できるようにする。
- 路線の駅一覧からの除外は、駅設備の削除や、列車の通過指定とは区別する。
- その後、系統側で路線上の出発・経由・終点を設定する。路線と系統を独立した概念として維持する。
- 路線名と系統名は同じでも異なっていてもよい。ユーザーの例は上野東京ラインであり、路線名と運行系統名が常に一対一で一致する前提にしない。
- 各系統では各駅停車を基本とし、列車種別と停車駅を設定する。停車・通過は路線作成時ではなく系統・列車種別の設定として扱う。
- 先に参考とした「中間駅を通過扱いで表示してから一括で停車にする」方針は撤回し、この最新フローで置き換える。
- 既存 `Route` / `OperatingService` の分離は維持する。復元版では起終点の経路候補・中間所属駅の除外、RoutePath保存、路線から独立したServicePath作成と停車指定の基礎がある。曖昧な候補を自動選択せず、路線変更へ系統を自動追従させない。列車種別・車両割当と実運行は未実装。
- 分岐や複数候補経路の選択、同駅への再訪、除外駅の経路上の扱い、端点の停車規則、種別と系統の具体的なデータ関係は未決定。路線駅の自動追加を物理設備や系統の自動生成とは同一視しない。

### 速度制限と車両費用

- 線路規格・カーブなどによる速度上限に加え、ユーザーが手動の速度制限を設定できるようにする。
- 低い速度で運行すると車両の維持整備費が減り、高速運転では負担が重くなるゲーム設計を希望する。
- 「120〜130km/h 以上は重め」はユーザーの調整イメージ。確定した閾値や費用式ではなく、現実の整備費を証明する数値でもない。
- 手動制限の適用単位、線路・曲線・車両性能等の上限との合成、速度と維持整備費の計算関係、平均速度・最高速度・走行距離などのどの量を費用へ使うかは未決定。

### 簡易車両設計と系統への割当

- 車両設計は簡易なものとし、定員を主要な設計要素として扱う。
- 材質の選択で重量・運行費・修繕費が変わるようにする。材質一覧と各数値は未決定。
- 省エネ制御を車両設計の要素に含める。制御方式や効果量は未決定。
- 特急車両の車内設備を設定できるようにし、利用者満足度へ反映する。設備項目、定員とのトレードオフ、効果量は未決定。
- 系統の列車種別ごとに使用車両を指定する。系統全体に常に一種類の車両を固定する前提にしない。
- 車両仕様・編成・種別への割当・運行経路を分離し、定員やホーム収容判定、運行費・修繕費・満足度の計算につなげる。詳細な型式・性能設計のシミュレーターまで求めるものではない。

### 表示設定

- UI のライト／ダークを切り替えられるようにする。
- 線の太さ、地図のコントラスト、パネルサイズ、文字サイズを調整できるようにする。
- 調整範囲、既定値、保存単位、画面倍率との関係は未決定。表示上の線太さと物理的な軌道幅は混同しない。

### 費用の時代基準と遊びやすさ

- 費用設定は2000〜2020年代を基準とし、現実よりやや安めで遊びやすいバランスを目指す。
- これは Rosenfu のゲームバランス方針であり、実際の建設費・維持費を調査済みという意味ではない。
- 具体的な基準年、価格データの出典、物価補正、ゲーム用の調整率、費用項目間の相対関係は未決定。参考ゲームの金額をそのまま採用しない。
- ゲーム年を「1年目」等と表示する方針とは区別する。費用の年代基準からゲーム内の暦の基準年を決めたことにはしない。

### ゲーム内の暦

- 年は西暦ではなく「1年目」「2年目」のように表示する。
- 土日祝日は現行日本のカレンダーに従う方針。
- 基準年・初日の曜日、閏年の扱い、ゲーム年と実際の暦の対応、祝日法改正や振替休日・移動祝日の更新方法は未決定。現実の西暦を表示しないことと、内部の暦を無根拠に毎年同一にすることは区別する。

### 時間加速とマルチ同期

- ユーザーは Trainsworld の最大100倍でも遅く感じるため、Rosenfu では時間加速を調整したい。100倍はユーザーの参考ゲーム説明・体感の基準であり、Rosenfu の確定上限や実測性能ではない。
- 遊びやすい進行速度とマルチプレイの同期制約の両方を考慮する。具体的な倍率、操作、シングルとマルチで同じ範囲にするかは未決定。
- 既存の共通ゲーム時刻・権威側の計算管理・初期段階のホストによる速度変更という方針と整合させる。各クライアントが独立したゲーム速度で進行する仕様にはしない。
- 計算負荷、同期頻度・通信量、遅い参加者や再接続時の追いつき、高速時の描画と計算の分離、負荷超過時の挙動は設計・検証事項。高倍率の実時間性能を保証しない。
- 本項目は追加要望であり、時間進行・加速・マルチ同期は未実装。倍率変更で計算結果や保存・再開の整合性が崩れないことを検証する。

## 2. Trainsworld の参考仕様として受け取った内容

次は建設・駅 UI の参考として整理する。Rosenfu への完全な複製や具体値の採用は未確定。

### 高さと自動乗越

- 高さは地上、上 3 段階、下 3 段階の計 7 レベル。
- 同じ高さの線路が干渉した際、自動で乗り越えるかを選べる。
- ON はスロープで同高さの線路を乗り越え、新しい分岐を立体交差にするよう「試みる」建設補助。どの形状でも成功する保証とは解釈しない。
- OFF では同じ高さの平面交差が可能。
- Rosenfu の高さレベルの確定、各レベルの実高さ、勾配、最上段・最下段の扱い、自動処理に失敗したときの表示・代替操作は今後設計する。

### 3 種の敷設補助

- 実在の路線網に合わせる。
- 道路に合わせる。道路追従時には街路網に緑のガイド線を示し、描画中 Ctrl を押すと一時的に手描きにする。
- 線路の横に沿わせる。青い対象範囲へカーソルを合わせると別の線路と並行に描く。
- これらは別の補助機能として扱い、複数有効時の優先順位、追従対象のデータ、平行間隔、Ctrl 解除時の復帰規則は未決定。

### 駅長と駅改良

- 参考画面は「駅の長さ − 10両 ＋」という両数入力。参考ゲームの 3〜20両という範囲は Rosenfu の上限・下限として採用していない。
- 駅改良の参考例は折返し設備、駐車場、待合室、待避線、連絡通路、接する駅をつなぐ駅舎。
- 旅客の体感時間・能力等への効果、建設費、維持費は参考例であり、Rosenfu の採用値ではない。
- 参考ゲームで示された 3000万円/日・750万円/日という定額も Rosenfu の費用として採用しない。

## 4. 設計検討事項と実装の境界

以下は開発上の検討案であり、ユーザーが具体的な方式まで決定したものではない。

- 線路種別、目標速度、幾何形状、走行可能速度を別概念として持ち、種別だけで半径や速度を固定しない。
- 地図提供元の参照形状とゲームの建設線形を分離する。OSM 等の道路・線路追従には背景画像だけでなくベクトル形状と利用条件の確認が必要。 リレーショナル保存・空間索引・他形式の比較は[地理データの保存方式検討](map-backgrounds.md)を参照。方式は未決定。
- 平面交差は幾何的交差・接続関係・列車進路の競合領域を分離してモデル化する。単に交わった線を自動で同じ接続点にするとは限らない。
- 計画から着工への原子的な適用、駅と線路の着工順、計画取消時の参照整合性、費用再計算、Undo/Redo とマルチ権限の境界を定める。
- 20m級換算表示と実際の編成長の収容判定を分離し、端数、連結長、停車余裕、ホーム有効長の扱いを決める。
- 駅運営費用とサービス品質を分離する。旅客が費用の数値そのものを選択理由とするのではなく、サービスや満足度を通じた影響を検討する。
- 列車速度や駅への近さを所要時間と満足度へ二重計上しないよう評価モデルを整理する。
- 地名取得元、更新・キャッシュ・ライセンス、オンライン依存を決める。
- 暦の基準と祝日データの版を保存し、保存再開やマルチで休日判定が変わらない設計を検討する。

具体的な式・係数・金額・速度・半径・高さ・実装版・納期は本書では確定しない。
