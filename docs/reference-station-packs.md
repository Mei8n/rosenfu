# ローカル参照駅パック（試作）

「地図・表示設定」→「参考駅（ローカル）」でユーザーが選択したJSONだけを読み込む。ファイルはブラウザ/WebView内で解析し、サーバー送信・Worldへの混入をしない。ユーザーがJSONを選択すると、検証済みパック1件を端末のIndexedDBに保存する。次回起動時は保存済みJSONをサイズ・形式・内容まで再検証して復元する。実在駅データは同梱していない。

参照駅は紫の菱形と「参考:」ラベルで描き、ゲーム駅（点／ホーム帯）とは分ける。参照駅をクリックして建設・削除したり、路線へ自動追加したりはしない。表示ON/OFFとパックの解除が可能。現在の地図範囲内だけを最大300件表示する。超過時は先頭300件を表示し、範囲内総件数を案内する。密集する場合は拡大する。画面には出典とライセンスを併記し、読み込んだパックのメタデータとは別に © OpenStreetMap contributors の固定帰属と copyright リンクを表示する。表示OFF時もパック設定内の帰属は残る。

これは駅の参考点のみ。背景画像、OSMタイル、鉄道／道路スナップ、駅名検索、完全なオフライン実地図ではない。自作背景と併用しても自作背景が実地図になるわけではない。現在のカメラは日本付近の対応範囲に限定され、パック範囲へ自動移動しない。

## JSON schema version 1

- `format`: `rosenfu-reference-stations`
- `version`: 数値 `1`。未知版は拒否。
- `dataset`: `id`、`revision`、`source`、`license`は非空文字列。前2者は200文字以下、後2者は1000文字以下。
- `dataset.bounds`: `west`、`east`、`south`、`north`の有限数値。経度±180、緯度±85.05112878以内、west < east、south < north。日付変更線をまたぐbboxは非対応。
- `stations`: 最大20000件の配列。
- 各駅: `osmType`は`node`/`way`/`relation`、`osmId`は正の整数を表す文字列（1〜20桁、先頭0なし）、`name`は非空200文字以下、`longitude`/`latitude`はbbox内、`kind`は`station`/`halt`/`tram_stop`。
- UTF-8で5MiB以下。OSM要素種別とIDの組の重複、不正座標・型・版はパック全体を拒否する。失敗時は現在のパックを保持する。後から選んだファイルが優先され、古い読込の完了は反映しない。

以下は構造説明用の空パックであり、実データやライセンス許可を示さない。

```json
{"format":"rosenfu-reference-stations","version":1,"dataset":{"id":"example","revision":"1","source":"your documented source","license":"your applicable license","bounds":{"west":139,"east":140,"south":35,"north":36}},"stations":[]}
```

ライセンス欄はデータの表示情報で、アプリが権利や出典の真偽を検証するものではない。適法な取得・配布元のデータを用意すること。OSM由来のパックはOSM contributorsへの帰属とODbL等の適用条件を提供者側でも満たす必要がある。公式OSMタイルの一括取得機能はない。

`referenceStations.ts` の `ReferenceStationRepository.query(bounds,limit)` を表示側の境界とし、現状は検証済みJSONのメモリ実装。将来SQLite等へ交換できる。現状の永続化はIndexedDBであり、SQLiteは未実装。


## 端末内保存

- パック選択はローカル保存も行う明示操作。UIにその旨を記載している。ネット送信はなく、Worldセーブやバックアップとは独立。
- IndexedDB `rosenfu-reference-stations` の `packs/current` だけを使用。他のアプリデータベースやWorldファイルには触れない。
- 検証成功後の置換はreadwriteトランザクション。パック不正・容量不足・アクセス拒否では前の保存を保持する。新しいパックはセッション内で利用でき、保存失敗を明示する。
- 「参照パックを外す」は表示解除と端末保存の削除を行う。削除失敗は明示し、次回起動で旧データが戻る可能性を案内する。不正な保存データを復元できない場合もこの削除操作を使える。
- 保存・読出し・削除は順番に実行し、旧書込が解除後に復活しないようにする。起動時復元も世代番号を確認し、その間にユーザーが選んだパックを上書きしない。
- ブラウザ/WebViewのプロファイルやオリジンごとの保存。開発プレビューと配布アプリで共有される保証はない。プライベートモード・容量制限・サイトデータ消去で利用不可/消失し得る。元のJSONはユーザー側で保管すること。
- IndexedDBの構造や保存値が壊れている場合は勝手に削除・修復せず、復元失敗として知らせる。実ブラウザ/Windowsでの長期保持は別途確認が必要。

## 新駅名の参考候補

建設線形上で新駅の位置と有効なホーム寸法を選ぶと、補正後の配置中心から近い参考駅名を提示する。ローカルパックだけを検索し、ネットの逆ジオコーディングや地名検索を行わない。周辺地名全般の自動候補は未対応。半径1km・距離順最大5件は暫定UI上限で、駅名の正確さ・網羅性や「同じ駅」を保証するものではない。

- 候補ごとに概算の直線距離と参照OSM ID、一覧に出典・版を表示する。
- 未導入・位置未選択・パック範囲外・近傍の利用可能な名前なしを分けて説明する。「候補なし」は実在駅がないという意味ではない。
- 重複名はNFKC/大小文字を比較キーとしてまとめ、最寄りの1件を残す。表示・入力する名前自体は前後空白を除く以外に正規化しない。
- 空名、80文字超、既知の不明名、制御/不可視/双方向制御文字やHTML風記号を含む名前は候補にしない。参照パックそのものの駅情報は変更しない。
- 「新駅名入力へ使う」を押した場合だけ、新駅の名前入力へ反映する。候補が現れただけでは手入力値を変えない。既存駅の名前入力や既存駅データは変更せず、駅設置も自動確定しない。
- 候補は参考情報で、駅設備、ホーム長、駅設置Undo履歴には影響しない。パック範囲内でも収録漏れ・古い名前・名称不明の可能性がある。
