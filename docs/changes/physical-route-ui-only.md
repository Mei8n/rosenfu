# 路線・系統 UI の新形式への一本化

アルファ段階の旧ワールド互換を終了し、建設線形と端点接続を使う経路に一本化する。

- 路線は `RoutePath` の物理区間と所属駅を持つ。候補の起点・経由駅・終点を選び、所属駅を確認して保存する。
- 系統は `ServicePath` の区間と駅出現位置を持つ。路線の部分区間・逆方向から作り、停車/通過と路線への所属を個別に設定する。
- 旧 `Track`（駅間の論理接続）専用の手動路線・系統フォームと、旧経路の下書き取込は廃止する。
- 距離は保存された建設線形から測る。駅位置や駅間直線から旧線路の形状・長さを推測しない。物理情報不足の場合は距離を表示しない。
- 最短候補は、探索を完了した場合に backend が認定した候補のみを選ぶ。探索上限に達した場合は最短・唯一・接続なしと断定しない。
- 路線所属駅と系統の停車駅は別。駅の交差・近接や同一駅グループだけで線路の接続は作らない。

旧セーブは読み込み段階で明示的に非対応とし、自動変換・自動削除しない。実際の対応 schema とエラー処理は保存形式側の契約を参照する。この UI 整理だけで古いファイルを書き換えない。
