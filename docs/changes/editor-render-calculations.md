# 編集操作時の再計算削減

会社名の入力など、地図・建設計画を変更しない操作でも、App の再描画ごとに全計画の線形検証、駅グループ判定、保存用の計画比較文字列の生成を行っていた。

既存の `useMemo` による派生データの管理を駅・計画の計算にも適用した。カメラだけが変わった場合も、地理座標上の計画検証や駅グループは再利用する。カーソルによる延長がない場合のプレビューは、計算済みのドラフト形状を使う。分岐方向と直前点の参照も安定させ、無関係な入力による計算結果の破棄を防ぐ。保存形式・線形判定・駅の結合条件は変更しない。

100駅、256点の既設線形、各256点の編集済み計画12本を読み込んだ jsdom 環境で、会社名を10回変更した。React Profiler の更新描画時間の合計は修正前898ms、修正後337ms（単回計測）。駅グループ判定と計画比較はそれぞれ10回から0回、線形計算は250回から0回になった。実機の操作遅延やブラウザのレイアウト・ペイント時間を示す数値ではない。

`RenderingPerformance.test.tsx` は入力と地図移動で不要な計算が再発しないこと、実際に計画を変更した場合は保存用比較が更新されることを検証する。編集・駅設置・保存・Undo の整合性は既存テストでも検証する。

検証: `npm run build` 成功。全体テストは `npm test -- --maxWorkers=2` で1007件成功、2件スキップ。通常の並列実行では2件が5秒の時間制限に達したため、並列数を制限して再確認した。

App 全体と SVG の再描画は残る。Tauri の WebView 上での体感・フレーム時間、バックエンドコマンドの所要時間は未計測であり、すべての遅延を解消したとは判断しない。
