## 監査結果と変えない方針

[要件](requirements.md)、[ロードマップ](roadmap.md)、近々の計画（参照原本未回収: `near-term-implementation-plan.md`）との照合では、物理線路・路線・系統の分離、通常/高速/トラム、自由敷設と実在形状追従、鉄道のない地域の潜在需要、用途・時間帯、会社基本運賃と路線別率、オフライン、集約ODは整合している。
不足は、実在駅非依存の明示試験、長距離・空港・フィーダー・道路競争の比較条件、初心者導線、ホーム/渡り線の説明。本書で補うが新たな必須リリース範囲を確定しない。

利用者報告は個別の当時の体験であり、現在のバグ、多数支持、原因の証明ではない。新幹線赤字（利用者報告P8）だけでは需要不足・価格・アクセス・運行費のどれが原因か判断できない。終端・停車順には後の改善説明があり、現行欠陥と断定せず回帰試験へ用いる。公式説明は検索索引経由で、内部式・現行版との一致は未確認。

## 初期需要を現実の鉄道駅に依存させない

発生・集中の入力は人口・雇用・土地用途・施設とし、4目的分類を維持する。**OSM等の実在鉄道駅は参考表示・敷設補助であり、それ自体を初期ODの発生源、人口の代理、需要の存在条件にしない。** ゲーム駅は地域需要へアクセスする設備。
空港・観光施設等は出典・時点・推計/未知を持つ目的地属性として検討する。周辺人口と施設利用者を重複加算せず、空港アクセスと従業者通勤を区別。施設未収録を真のゼロと扱わない。施設ODの校正値は未決。

受入試験:
- 人口・用途・施設を固定し、参考駅データの有無/表示/駅名を変更しても基礎ODが同じ。
- 実在駅のない住宅・工業地にも潜在ODがあり、新設ゲーム駅で配分が変わる。
- ゲーム駅追加・撤去で基礎ODを増減せず利用/未利用の内訳を変える。固定OD参照実装に誘発需要を暗黙導入しない。
- データ欠落は未知/推計として、真のゼロのfixtureと区別する。

## 長距離・空港・フィーダー・道路競争の実験

固定小ワールド、固定OD、共通時間窓を使い一要因ずつ変更する。確率配分ならseedを固定。TrainsWorldの再現ではなくRosenfu候補モデルの比較実験。

| ケース | 変更点 | 確認 |
| --- | --- | --- |
| 都市間 | 通常/高速の時間・頻度・運賃を個別変更 | 距離だけで高速へ固定せず、時間短縮と料金/待ちの差を説明できる |
| 空港 | 同じ空港ODで駅から施設へのアクセス時間を変更 | 空港駅という名前だけで集客せず、全行程を比較する |
| フィーダー | 幹線・OD固定で徒歩のみ/支線・トラム接続を比較 | 乗換・待ち・通算運賃を含め接続改善と負担を分離。必ず利用増とはしない |
| 道路競争 | 鉄道固定で外部代替の時間/金銭費用を変更 | 鉄道を強制せず代替手段シェアと未充足を区別。道路条件で配分が反応する |
| 高速線収支 | 車両費・維持費・容量を別々に変更 | 赤字を需要不足と短絡せず乗車数・収入・費用・混雑へ分解する |

道路競争はまず外部代替の集約コストで検証し、個別自動車やバス経営を前倒ししない。道路形状への建設スナップとも別機能。記録値は基礎OD、鉄道/代替/未充足人数、路線/会社別乗車数・収入、アクセス/待ち/乗車/乗換時間、費用内訳、CPU/RAM。容量導入後は積み残しも測る。乗車数は乗換で増えるためOD人数と混同しない。全再計算参照解との差、保存則、配分の振動、重複経路によるシェア水増しも確認する。

## 運賃との接続

会社基本運賃と路線別率（変更なし1.0倍）を維持。投稿の倍率例や現実運賃をゲームの固定値にしない。均一/距離/区間制、端数、跨線/他社乗換、無料可否は未決のまま。
旅客選択の見積運賃と収入計上は同じ規則・適用版を使う案とし、乗車中の改定扱いを明示決定する。複数路線を経由する系統で各路線率を全旅程へ重複適用しない契約・試験を置く。価格変更で基礎ODを消さず配分と収入を変える。値上げで利益が必ず増えるとはしない。
将来のバスは鉄道倍率に押し込まず、モード別体系・乗継精算を拡張できる境界を検討する。今はschemaを予約せず、鉄道のみの旧保存を意味不変で読める移行fixtureを設計する。

## 初心者導線とホーム/渡り線

初回導線案: 参考地図/需要 → 線路計画 → 駅 → 着工 → 路線所属 → 系統/停車順 → 運行条件 → 利用/収支診断。未実装工程は未対応と明記し、0.1に需要・運行完成を要求しない。スキップ・再表示・取消・入力保持を設計する。
- 計画/着工、路線所属/停車を別表示。未着工は再起動保存されないことを明示し、撤回された計画永続化を復活させない。
- ホーム長は編成収容、ホーム数と利用可能進路は同時扱い、渡り線は線路間移動・折返し経路に関係すると分ける。ホーム増設だけで詰まりが必ず解消するとは説明しない。
- 渡り線の有無だけで折返し可能とせず、方向・合流・進路競合・最後尾解放を図とプレビューで示す。立体でも共通合流部の競合は残る。
- 経路不能と運行待ちを区別し、未接続/競合/長さ不足/運行間隔/需要・アクセス不足のうち実際に判定できる理由だけ表示する。
- 環状の同駅再訪・方向・停車出現と、所属除外/通過を区別。既存系統を路線変更へ自動追従させない。
初見テスト担当に2駅線・中間駅通過・環状・終端折返しを試してもらい、完了可否、誤操作、復旧、説明後の再試行を記録。ホーム長不足と進路不足は別fixture。合格閾値は小規模試験後に決め、未測定値を保証しない。

## 実装順・完了

0.1/近々の計画では建設・路線・系統の説明と保存状態。0.2〜0.3では固定OD、実在駅非依存、小規模比較、運賃と診断。ホーム/渡り線の実動は分岐・運行基盤後。バス別体系は後続候補のままとし初回必須へ変えない。B1/B2/B3の所属/停車/出現参照契約も変更しない。
完了には採否決定、fixture・全再計算比較、保存/再開、SP/MP共通coreの同一入力比較、性能・初見操作試験を要する。現在は未実施。恒久要件・操作説明・需要/運賃仕様・回帰テストへ移し、設計一覧（参照原本未回収: `design-plans.md`）と参照を更新して本書を削除する。

### 旅客探索は建設候補APIと別契約にする（未実装）

現 `world/route_planning.rs` は建設用の候補列挙であり、候補32件・探索100,000ステップ・256区間を上限とし、駅の再訪を除いた経路を設備ID順で探索する。これは最短時間・低運賃や有力な旅客経路の選択ではない。`incomplete` は経路なし・一意を証明しない。現在の建設操作の制限を、そのまま全国の旅客経路モデルへ転用しない。
