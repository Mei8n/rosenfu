# 既存coreを用いた全域水域仮定の独立adapter

全国の地上敷設対応ではない。runtime/UI/共有コードには未接続。

`prove_water_changes(&before, &after)`は実際の変更前後のWorldDraftを検証し、変更された線路と追加接続の両端から対象を抽出する。既存coreの`validate_connected_water`が未変更の接続先、環状、分岐を含めて評価する。呼出側からIDリストを受け取らないので、別の変更成分のIDだけ渡し忘れる誤りを防ぐ。権威ある変更前worldと変更後candidateを渡すことは統合側の責務。

全域を水域と仮定した非公開snapshotを一時的に作り、既存のHermite・アンカー別profile・0接触・-12m免除・接続経路判定をそのまま実行する。このsnapshotは実データではなく、保存・merge・配信・表示しない。返却値にもgeometry/coverage/water_ready/buildableを含まない。入力worldの保存済み環境とは混合せず、入力を変更しない。合成polygonの外縁問題を避けるため、入力点は経度(-179,179)、緯度(-84,84)内に限定する。

全域水域で水域制約を満たすなら、その部分集合でも満たすという単調性を利用する。これは**現在のcoreの数値モデルに対する条件付き結果**であり、PR147の整数kernelの厳密な距離上限と同一ではない。coreの浮動小数誤差、30km比較許容差、境界分類を引き継ぐ。未取得データを陸地や実測水域とは表現しない。

地上区間や高さ0との接触は全域水域の仮定では通らない。単独の高架/開削30km以下や十分深いトンネル等について、データ不足だけで停止せずに済む条件を調べられる。返却結果は道路、線形、駅、保存整合の最終判定を代替しない。変更のたびに最新candidateで再評価し、以前のproofを別計画へ再利用しない。変更対象なしはNoAffectedTrackであり、建設許可ではない。

## テスト

`cargo test --locked --manifest-path scripts/water-proof/core-adapter/Cargo.toml`

12 tests: 30km境界、地下免除、内部0接触、-12m一点接触、未変更の接続先、別成分の地上変更、保存coverageに依存しないこと・入力不変、不正profile/参照/変更なし、閉環、アンカー別profile、接続だけの追加、評価領域の境界拒否、128通りの水域部分集合。最初の地上fixtureは既存最小線形長を満たさず失敗したため、validな1000m線路へ直して地上拒否を確認した。

## 実アプリへ接続する前の残件

- 新設・延伸・編集・接続で同じbefore/after差分を評価し、既存の全水域ready必須gateとの関係を整理する。共有session/core/UIの変更は担当調整後。
- 道路取得成功と水域不明を分離して保持する。保存coverageを「仮定によるproof」で昇格しない。
- 不成立時の具体的理由を、線路付近の既存drawing/plan-hover小ウィンドウへ表示する。独立パネルを追加しない。PR147の未実行受入条件も継承する。
- 全国地上判定のためには別途、原典の対象水域・線表現の幅・省略基準・時点・位置精度を含むcoverage契約が必要。全国メッシュ取得成功やWA面なしだけでは足りない。
